# Flutter AppRead 需求文档（PRD）

## 1. 文档信息

- 版本：v0.1（MVP）
- 状态：Draft
- 目标版本：MVP Beta
- 适用范围：书源兼容阅读（文本小说）

## 2. 用户与场景

## 2.1 目标用户

- 熟悉阅读类 APP、希望自由导入书源的重度阅读用户。
- 有基础折腾能力，愿意手动导入和筛选书源。
- 对阅读体验有要求（排版、主题、进度记忆）。

## 2.2 核心场景

- 用户导入书源 JSON 后，直接搜索并开始阅读。
- 用户发现某个书源不稳定时，能快速禁用或排查错误。
- 用户在离线状态下继续阅读已缓存章节。

## 3. 产品目标与非目标

### 3.1 产品目标（MVP）

- 提供一个稳定可用的“导源即读”链路。
- 支持常见规则格式，降低书源接入门槛。
- 提供清晰的失败反馈，提升可维护性。

### 3.2 非目标（MVP）

- 不追求全量规则 100% 兼容。
- 不支持复杂登录、验证码自动化。
- 不做社区分发、在线源市场。

## 4. 功能需求

## 4.1 书源管理

### FR-001 导入书源

- 支持从本地文件导入 JSON（单个对象或数组）。
- 支持粘贴 JSON 文本导入。
- 导入前执行字段完整性检查。

验收标准：

- 非法 JSON 能明确提示错误位置。
- 合法书源可入库，并在列表可见。

### FR-002 书源列表与状态控制

- 展示书源名称、分组、启用状态、最后测试时间。
- 支持启用/禁用、编辑备注、删除。

验收标准：

- 禁用书源不会参与搜索与抓取。
- 删除后相关缓存可选择清理。

### FR-003 书源连通性测试

- 支持对单个书源执行“测试搜索词”验证。
- 展示请求地址、响应状态、规则命中结果。

验收标准：

- 测试失败可区分：网络失败 / 解析失败 / 规则为空。

## 4.2 检索与书籍流程

### FR-004 全源搜索

- 输入关键词后并发调用已启用书源。
- 搜索结果支持按来源聚合或混排。

验收标准：

- 至少支持分页参数传递（若源支持分页）。
- 搜索结果卡片包含书名、作者、最新章节、来源。

### FR-005 书籍详情

- 从搜索结果进入书籍详情。
- 展示封面、作者、简介、最新章节、更新时间。

验收标准：

- 缺失字段时 UI 不崩溃，并给出默认占位。

### FR-006 目录与章节

- 加载目录列表，支持正序/倒序切换。
- 点击章节进入正文页。

验收标准：

- 能正确处理相对链接。
- 同一本书多次进入目录时优先使用缓存。

### FR-007 正文阅读

- 展示章节标题与正文内容。
- 支持上一章/下一章切换。
- 自动记录最后阅读进度。

验收标准：

- 正文支持基础清洗（脚本、广告片段、异常空白）。
- 字号/行距/背景样式调整后可即时生效并持久化。

## 4.3 阅读器体验

### FR-008 阅读设置

- 字号、行距、边距、背景主题、亮度跟随。
- 切换翻页模式（滚动/仿真翻页可分阶段实现）。

### FR-009 书架与历史

- 支持加入/移除书架。
- 支持最近阅读列表和继续阅读入口。

## 4.4 错误处理与可观测性

### FR-010 错误中心

- 对抓取失败记录详细日志：时间、书源、URL、规则阶段、错误信息。
- 支持复制日志文本用于排查。

### FR-011 降级策略

- 某书源连续失败达到阈值时提示用户并建议禁用。

## 5. 非功能需求

## 5.1 性能

- 搜索列表首屏可感知加载时间 < 2 秒（取决于网络）。
- 目录、正文解析过程不阻塞主线程。

## 5.2 稳定性

- 网络请求统一超时、重试、异常拦截。
- 所有规则执行失败必须可捕获，不允许直接崩溃。

## 5.3 可维护性

- 规则适配层与业务层解耦。
- 新增规则语法时不影响现有接口。

## 5.4 安全与合规

- 不默认执行不可信脚本。
- 明确用户协议中说明“书源为用户自定义导入”。

## 6. 兼容策略需求（针对 Legado 规则）

## 6.1 规则参考基线

- 外部规则参考文档：`https://mgz0227.github.io/The-tutorial-of-Legado/Rule/source.html`
- 本项目以该文档作为“字段语义参考”，但不承诺 100% 全量语法兼容。
- 兼容策略采用“高频规则优先”，先覆盖可稳定运行的主链路。

## 6.2 MVP 已落地的书源字段映射

- 基础字段：`bookSourceName`、`bookSourceUrl`、`bookSourceGroup`、`bookSourceComment`、`header`。
- 搜索入口：`searchUrl`/`ruleSearchUrl` -> `searchRule`。
- 搜索规则：支持 `ruleSearch` 对象中的 `bookList`、`name`、`bookUrl`、`author`、`intro`、`coverUrl`、`lastChapter`。
- 详情规则：支持 `ruleBookInfo` 对象中的 `name`、`author`、`intro`、`coverUrl`、`tocUrl`。
- 目录规则：支持 `ruleToc` 对象中的 `chapterList`、`chapterName`、`chapterUrl`、`isReverse/reverse`。

## 6.3 MVP 规则执行范围（当前实现）

- 规则类型：`html:`、`regex:`。
- 对“无前缀规则”做归一化处理（按 CSS 选择器 + 提取器处理）。
- HTML 提取器支持：`@text`、`@html`、`@attr(xxx)`，并兼容 `@href`、`@src` 这类简写映射。
- URL 模板支持变量替换：`{{key}}`、`{{keyword}}`、`{{page}}`、`{{pageSize}}`。
- 搜索、详情、目录阶段均支持相对链接自动转绝对链接。

## 6.4 当前暂不支持（后续迭代）

- JavaScript 规则（`js:`）、复杂规则链路（如多段 `&&` 完整执行、`@put` 等）。
- 登录态、Cookie 持久化和复杂鉴权。
- 复杂加解密请求处理。
- JSONPath 引擎（规划中，尚未在 v0.1 主链路启用）。

## 6.5 二期支持目标

- JavaScript 规则执行（安全沙箱）。
- 登录态、Cookie 维护。
- 复杂加解密请求处理。
- JSONPath 规则执行能力。

## 7. 质量门禁（Definition of Done）

- 代码：通过 `flutter analyze`。
- 测试：关键 use case 有单测或集成测试。
- 文档：新增模块必须同步更新架构文档。
- 验收：至少通过 10 条书源回归样本中的 6 条。

## 8. 待确认事项

- 书源分享与订阅是否进入后续规划。
- iOS 平台上网络权限与规则执行能力边界。
- 是否在 MVP 引入账号体系（当前建议不引入）。
