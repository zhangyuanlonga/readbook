# Flutter AppRead 详细实施步骤（从 0 到 MVP）

## 阶段 0：项目初始化（Day 1 - Day 2）

目标：建立可持续开发基础。

任务清单：

1. 确认技术栈与依赖：状态管理、数据库、网络库、HTML 解析库。
2. 重构目录结构（按 feature + core + domain + data）。
3. 搭建基础路由和应用壳。
4. 建立统一异常、日志、Result 封装。
5. 建立文档目录与模板。

交付物：

- 可运行基础工程。
- 统一错误模型与日志接口。

验收标准：

- `flutter analyze` 通过。
- 首页可正常启动，路由可跳转。

## 阶段 1：书源导入与管理（Day 3 - Day 6）

目标：先把“数据入口”打通。

任务清单：

1. 定义 `LegadoSourceRaw` 模型（保留原始字段）。
2. 定义内部模型 `SourceDefinition`。
3. 编写 `SourceAdapter`（外部字段映射到内部字段）。
4. 完成 JSON 导入（文件导入 + 粘贴导入）。
5. 完成书源本地存储（drift/isar 二选一）。
6. 完成书源管理页（列表、启用、禁用、删除）。
7. 完成基础校验（必填字段、URL 合法性）。

交付物：

- 书源导入功能可用。
- 书源管理页可操作。

验收标准：

- 导入合法 JSON 后列表可见。
- 非法 JSON 给出明确错误提示。

## 阶段 2：搜索链路（Day 7 - Day 10）

目标：完成从关键词到书籍列表。

任务清单：

1. 定义搜索请求上下文（关键词、分页、sourceId）。
2. 实现 URL 模板变量替换。
3. 实现基础网络请求器（超时、重试、header）。
4. 实现规则执行器（先 HTML + Regex）。
5. 解析并标准化搜索结果为 `Book`。
6. 完成搜索页面和结果列表。
7. 增加搜索日志记录。

交付物：

- 可用关键词搜索。
- 可展示来源维度的结果。

验收标准：

- 样本书源至少 60% 返回结果。
- 搜索失败可查看错误原因。

## 阶段 3：详情与目录（Day 11 - Day 14）

目标：打通书籍结构信息。

任务清单：

1. 实现详情页规则执行（封面、作者、简介）。
2. 实现目录规则执行（章节标题、章节链接）。
3. 处理目录排序（正序/倒序）。
4. 章节列表缓存。
5. 完成详情页与目录页 UI。

交付物：

- 书籍详情可展示。
- 目录可点击进入章节。

验收标准：

- 目录加载失败时不崩溃。
- 相对链接解析正确。

## 阶段 4：正文与阅读器（Day 15 - Day 19）

目标：实现可持续阅读体验。

任务清单：

1. 实现正文规则执行。
2. 实现正文清洗（去脚本、去广告、空白规范化）。
3. 实现阅读页 UI（标题 + 正文 + 上下章）。
4. 实现阅读设置（字号、行距、主题）。
5. 实现阅读进度保存与恢复。
6. 实现章节预加载和缓存。

交付物：

- 完整阅读闭环。
- 阅读设置可持久化。

验收标准：

- 退出后能从上次进度继续阅读。
- 同一本书切章体验流畅。

## 阶段 5：稳定性增强（Day 20 - Day 24）

目标：提升真实可用性。

任务清单：

1. 增强编码识别（UTF-8/GBK）。
2. 增强网络容错（失败重试、错误分级）。
3. 增加规则调试页（输入规则实时看结果）。
4. 增加书源健康度（连续失败计数）。
5. 增加错误中心页面。

交付物：

- 可排障、可维护的调试能力。

验收标准：

- 常见失败可在 UI 中定位原因。
- 失败不影响其他源继续工作。

## 阶段 6：测试与发布准备（Day 25 - Day 28）

目标：从“能用”走向“可发布”。

任务清单：

1. 建立 10-20 条回归样本。
2. 补齐关键模块单测。
3. 执行兼容率回归和性能检查。
4. 完成 Beta 发布清单（权限、图标、版本号、日志）。

交付物：

- MVP Beta 包。
- 回归报告。

验收标准：

- 通过率达到既定门槛。
- 无阻断级别问题。

## 并行工作流建议

- 产品流：需求澄清 -> 验收标准 -> UI 低保真。
- 开发流：任务拆分 -> 开发 -> 自测 -> PR。
- 质量流：回归样本维护 -> 自动化验证 -> 缺陷闭环。
