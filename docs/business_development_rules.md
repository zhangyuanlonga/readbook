# 业务开发规则

更新时间：2026-06-04

本文定义后续业务功能如何设计、拆分、验收。目标是让业务越做越清楚，而不是让页面文件继续膨胀。

## 1. 业务链优先

新功能不要只按页面开工，应先定义完整业务链：

- 用户入口。
- 用户要完成的目标。
- 正常流程。
- 失败流程。
- 不支持平台的降级流程。
- 相关数据、缓存、权限、会话和回归方式。

业务链未定义清楚前，不新增复杂页面 UI。

后续里程碑任务默认按“业务链兼容 + 测试验收”执行，而不是按单平台功能点执行。举例：登录链如果要兼容桌面端和 Web，任务完成前必须同步检查 Android、iOS、Web JS、macOS、Windows、Linux 的业务入口、会话恢复、退出登录、凭证存储、错误态、降级态和测试记录。只验证目标端能点通，不代表任务完成。

## 2. 当前核心业务域

项目当前核心业务域按以下方式理解：

- 书架：书籍集合、分类、标签、排序、继续阅读、本地图书入口。
- 搜索与发现：服务器书源网关、搜索结果、书源健康、发现列表。
- 书籍详情：元数据、目录、加入书架、换源、阅读入口。
- 阅读器：文本、图文、PDF、漫画、音频、分页、自动阅读、设置、书签、进度。
- 统计：阅读记录、每日记录、阅读时长、阅读字数、排行和趋势。
- 外观：主题、字体、背景、图集、导航图标、启动图。
- 账号与会员：登录、会话、会员权益、设备席位、反馈、公告。
- 存储与缓存：数据库、托管文件、缓存目录、安全存储、诊断日志。

跨域逻辑必须通过 service、repository、use case 或 facade 协作，不允许页面直接串多个领域细节。

## 3. 业务层职责

Presentation 只负责：

- 展示状态。
- 触发用户意图。
- 展示错误、空态、加载态和禁用态。
- 根据 capability 决定入口展示方式。

Application 负责：

- 业务流程编排。
- 状态转换。
- 平台能力解释。
- 错误分类。
- 降级策略。
- 调用 repository 或 core service。

Domain 负责：

- 纯 Dart 实体。
- 值对象。
- 共享仓库接口。
- 业务语义规则。

Data / Core 负责：

- 数据库、网络、缓存、文件、设备、认证、日志等基础设施。

## 4. 新功能设计模板

新功能开工前补齐：

| 项目 | 内容 |
| --- | --- |
| 业务目标 | 用户最终完成什么 |
| 入口 | 从哪个页面、按钮、菜单或快捷键进入 |
| 平台范围 | Android / iOS / Web / macOS / Windows / Linux |
| 支持能力 | 需要哪些文件、数据库、网络、WebView、音频、剪贴板、窗口能力 |
| 降级策略 | 不支持平台展示禁用、隐藏、替代还是只读 |
| 状态模型 | 页面状态、业务状态、缓存状态分别是什么 |
| 数据落点 | SharedPreferences、Drift、托管文件、缓存、安全存储 |
| UI 形态 | 移动端、桌面端、Web 端分别如何展示 |
| 验收 | 自动测试、构建、手动回归 |

## 5. 不支持能力处理

不支持能力按优先级处理：

1. 有替代方案：展示替代操作。
2. 用户需要理解原因：禁用入口并展示原因。
3. 用户不需要感知：隐藏入口。
4. 高风险能力：默认隐藏，不让用户点了再失败。

禁用文案必须说清楚“当前平台不支持什么”，不要写泛泛的“功能不可用”。

## 6. 多端影响与移动端回归规则

每条业务链收尾必须记录：

- Android、iOS、Web、macOS、Windows、Linux 的影响范围和验证状态。
- 是否修改共享 model、provider、repository、service、route、storage、theme token 或 adaptive 组件。
- 如果主要目标是 Web / Desktop，但修改了共享层或平台能力，需要补 Android / iOS 定向回归或写明未验证原因。
- 如果主要目标是 Android / iOS，但修改了共享层、路由、存储或 capability，需要补 Web / Desktop 影响判断。
- Android / iOS 现有导航、手势、权限、文件选择、系统分享、支付、WebView、阅读器设置和用户资产路径不得只用“未涉及”带过。

任务执行时必须同时完成三类判断：

- 业务设计判断：当前平台的入口、流程、失败处理、降级方式和用户预期是否成立。
- 代码正确判断：分层、provider、adapter、capability、storage、route、UI token 和注释是否符合项目规则。
- 验证充分判断：目标平台是否真实验证；未验证平台是否写清原因、风险和补验方式。

## 7. 业务回归规则

核心业务链每次改动至少覆盖：

- 搜索 -> 详情 -> 阅读。
- 书架 -> 继续阅读。
- 本地图书 -> 详情 -> 阅读。
- 阅读器设置 -> 翻页/滚动/进度保存。
- 外观设置 -> 主题生效。
- 登录态恢复 -> 退出登录。
- 缓存清理后业务可重建。

如果只影响单个 feature，可以只跑对应链路；如果改共享层，必须扩大回归范围。
