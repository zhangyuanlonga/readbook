# 高级主题功能完结方案

更新时间：2026-05-06  
适用范围：`advanced theme` 创建、编辑、应用、列表、导入导出、删除、资源归属、运行态切换

---

## 1. 目标

本方案的目标不是继续做零散优化，而是一次性把高级主题功能收口到“可控、可维护、可验证”的状态：

- 大量主题下不因列表预览和全量扫描引发明显卡顿或内存风险
- 浅色 / 深色主题真正独立维护，并能随系统日夜或手动主题模式稳定切换
- 主题绑定资源有清晰的“共享资源 / 主题私有资源”边界
- 删除主题时可以明确选择删除哪些资源，且默认行为安全
- 导入 / 复制 / 删除后的资源生命周期一致，不留下隐性数据债

---

## 2. 当前结论

### 2.1 已完成收口

- 当前激活主题读取已改为按 `id` 直取，不再为取当前主题全量 `loadThemes`
- 高级主题列表已改为懒构建
- 列表卡片已移除真实壁纸解码，改为轻量双模式预览
- 阅读器背景已改为主题私有资源拷贝，不再直接引用全局素材库
- 主题删除已支持细粒度资源删除选项
- 双模式运行态解析测试、删除策略测试、主题私有阅读器背景测试已补齐

### 2.2 仍需一次性完结的点

- 列表页仍会一次性解码所有主题元数据 JSON
- 删除字体时只检查“是否被其他主题引用”，未检查阅读器手动设置是否仍在使用
- 主题资源缺少统一摘要视图，删除弹窗只能基于布尔项提示，不能显示实际资源明细
- 当前缺少“主题规模控制策略”，理论上仍允许无限导入超大主题

---

## 3. 目标架构

### 3.1 三层模型

- 主题定义层：`AppAdvancedTheme`
  负责浅色 / 深色颜色、壁纸、阅读器背景、图集、字体等绑定关系
- 主题资源层：`ManagedAssetStore` + gallery/font/background services
  负责资源持久化、路径归一化、删除和引用回收
- 主题运行层：`activeAdvancedThemeProvider` + `resolveAdvancedThemePalette/Backdrop`
  负责根据当前亮度和 `ThemeMode` 解析实际生效样式

### 3.2 资源归属原则

- 页面壁纸：主题私有资源
- 阅读器背景：主题私有资源
- 封面图集：共享资源，可被多个主题引用
- 启动图集：共享资源，可被多个主题引用
- 底栏图集：共享资源，可被多个主题引用
- 字体：共享资源，但允许作为主题绑定项

---

## 4. 一次性收口任务

### 4.1 列表与读取性能收口

- 保留当前“当前主题按 id 直取”路径，不再回退到全量扫描
- 为主题列表增加轻量摘要模型，避免列表页直接依赖完整主题对象做所有展示推导
- 主题列表只展示：
  - 名称
  - 分类
  - 是否双模式完整
  - 是否绑定壁纸 / 阅读背景 / 图集 / 字体
  - 轻量颜色预览
- 列表页不显示真实图片预览，不在列表中触发壁纸解码

### 4.2 双模式正确性收口

- 明确创建主题时必须生成 `lightConfig` 与 `darkConfig`
- 编辑页所有颜色、壁纸、阅读器背景、封面图集绑定，始终基于 `_selectedMode` 写入对应 config
- 应用主题后：
  - `ThemeMode.light` 只使用 `lightConfig`
  - `ThemeMode.dark` 只使用 `darkConfig`
  - `ThemeMode.system` 跟随系统亮度切换
- 补一组 widget / service 测试验证三种模式切换下的实际配置选择

### 4.3 资源生命周期收口

- 页面壁纸和阅读器背景统一走主题私有资源保存
- 导入、复制主题时，私有资源允许复制；共享资源保持共享引用
- 删除主题时按资源类型分别决策：
  - 主题私有资源：允许直接删
  - 共享资源：仅在无其他主题引用时删
  - 字体：仅在无其他主题引用且未被全局/阅读器手动设置使用时删
- 增加“资源引用检查服务”，统一判断资源是否还能删，避免删除逻辑散落在 `AdvancedThemeService`

### 4.4 删除交互收口

- 删除弹窗不再只是复选框集合，要显示实际会影响的资源摘要：
  - 页面壁纸：浅色 / 深色各几项
  - 阅读器背景：浅色 / 深色各几项
  - 封面图集名称
  - 启动图集名称
  - 底栏图集名称
  - 字体名称
- 删除默认策略：
  - 默认删除主题实体
  - 默认删除主题私有页面壁纸
  - 默认删除主题私有阅读器背景
  - 默认不删字体
  - 共享图集是否删除可保守默认关闭

### 4.5 规模控制与可控性收口

- 为导入主题增加限制策略：
  - 单主题包大小上限
  - 单张图片尺寸或字节数上限
  - 导入时可选自动压缩或拒绝超大图片
- 为高级主题列表增加资源统计：
  - 主题数量
  - 私有壁纸数量
  - 阅读器背景数量
  - 共享图集数量
  - 字体绑定数量
- 长期建议增加“清理未引用主题资源”工具页

---

## 5. 明确不再接受的状态

- 为获取当前主题而全量扫描全部主题
- 在主题列表中直接解码真实壁纸
- 阅读器背景继续直接指向全局素材库原图
- 删除主题时只有“删或不删全部配套内容”的粗粒度开关
- 字体删除不经过引用检查

---

## 6. 验收标准

### 6.1 性能

- 100 个主题时，进入高级主题列表无明显首屏阻塞
- 列表滚动不因主题壁纸预览产生明显掉帧
- 切换当前主题时不再依赖全量主题扫描

### 6.2 正确性

- 新建主题后，浅色 / 深色配置均存在
- 同一主题的浅色与深色配置可独立保存、独立编辑
- `ThemeMode.system` 下系统亮度切换后，主题实际展示能切换到正确 mode config

### 6.3 资源安全

- 删除主题不会误删全局素材库原图
- 删除主题不会误删仍被其他主题引用的图集 / 壁纸 / 字体
- 删除主题后，主题私有资源能被正确回收

### 6.4 工程

- `flutter analyze` 通过
- 主题服务测试通过
- 主题 token / mode 解析测试通过
- 至少补一组高级主题列表 smoke

---

## 7. 最终执行顺序

1. 固化当前已完成优化，不回退
2. 增加主题摘要模型与列表摘要渲染
3. 增加主题资源引用检查服务
4. 把字体删除纳入“主题引用 + 手动设置引用”双重检查
5. 重做删除弹窗摘要与默认策略
6. 增加导入大小与图片尺寸保护
7. 补齐 widget / service / smoke 测试

---

## 8. 结论

高级主题功能的完结标准不是“还能继续优化一点点”，而是：

- 运行态轻
- 列表可控
- 双模式正确
- 资源归属清楚
- 删除安全
- 大量主题下仍可维护

后续如果继续做高级主题，只允许在这个边界内扩展，不再接受重新把资源生命周期和运行态性能耦回页面层。
