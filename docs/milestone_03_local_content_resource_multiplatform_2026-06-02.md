# 里程碑 03：本地内容与资源能力多端化

创建日期：2026-06-02
复拆日期：2026-06-04

状态：待按多端分段执行。

适用平台：Android、iOS、Web JS、macOS、Windows、Linux。Web WASM 仍为独立专项。

核心目标：先把本地内容、资源、缓存和诊断这组高风险平台能力的边界定清楚，并完成 TXT 本地图书最小闭环、Web 本地内容策略、缓存治理和诊断 adapter 基线，让 Android / iOS 既有能力不回退，Web / Desktop 能按自身能力边界提供可解释体验。

## 1. 阶段定位

第三里程碑处理最容易牵扯全平台的能力：

- Android / iOS 本地图书、资源、缓存、诊断能力保持稳定。
- Desktop 本地图书导入。
- Web 本地图书上传 / 临时阅读 / 降级策略。
- 本地解析后台化。
- 缓存预算治理。
- 主题、字体、封面、启动图等资源能力先完成能力边界、引用模型和不误删保护。
- 诊断导出、日志、缓存清理等平台 adapter。
- 本地 override 依赖治理。

本阶段不是“把所有本地格式和资源能力一次性做满”，而是先把用户资产、可重建缓存、临时文件、浏览器持久化、诊断导出这几类高风险边界压稳。EPUB / PDF / MOBI、高级主题资源全量导入、Web 长期托管文件等能力可以进入评估和单项试点，但不作为 M3 通过的硬条件。

## 2. 执行方式

本里程碑必须按能力段执行，不能“一口气做本地能力”：

- 每段先盘点 Android / iOS 既有行为，再设计 Web / Desktop 差异。
- 每段必须明确用户资产、可重建缓存、临时文件、浏览器持久化的边界。
- 每段必须记录是否修改共享 parser、storage、repository、task queue、capability 或资源引用模型。
- 每段必须记录不支持平台如何禁用、隐藏、只读、上传、下载、复制或外部打开。

执行优先级：

| 优先级 | 范围 | 是否影响 M3 通过 |
| --- | --- | --- |
| P0 | 能力与存储盘点、文件选择 adapter、TXT 最小闭环、Web 本地内容策略、缓存治理、诊断 adapter、用户资产不误删 | 必须完成 |
| P1 | 资源能力边界、资源引用模型、资源缺失恢复、override 清单、解析后台化最小任务队列 | 应完成或记录延期原因 |
| P2 | EPUB / PDF / MOBI 全端闭环、高级主题资源全量多端导入、Web 长期托管文件持久化 | 单独评估，不阻塞 M3 |

## 3. 不做项

- [x] 不承诺 Web 拥有原生文件系统同等能力。
- [x] 不一次性支持全部格式全平台完美。
- [x] 不删除用户资产。
- [x] 不把缓存清理放进启动阻塞链路。
- [x] 不绕过现有存储治理规范。
- [x] 不为了本地能力重写在线阅读链路。
- [x] 不把 EPUB / PDF / MOBI 全端闭环作为本里程碑通过条件。
- [x] 不把高级主题、字体、启动图等所有资源的完整导入 / 导出 / 删除一次性做满。

## 5. 本地图书导入

格式优先级：

1. TXT。
2. EPUB。
3. PDF。
4. MOBI。
5. HTML / Markdown / 其他格式。

任务：

- [ ] Android / iOS 既有文件选择、权限、解析、托管路径形成基线记录。
- [ ] Desktop 文件选择通过 `file_selector` 或统一 adapter。
- [ ] Web 上传 / 临时阅读 / 禁用策略单独定义，不混用 Native 路径。
- [ ] 导入入口按 capability 显示。
- [ ] 文件复制进入托管文件目录。
- [ ] 索引过程后台化，不阻塞 UI。
- [ ] 导入任务进入任务队列或明确进度反馈。
- [ ] 导入失败有错误说明和重试方式。
- [ ] 至少一种格式完成：导入 -> 索引 -> 详情 -> 阅读 -> 进度保存。
- [ ] EPUB / PDF / MOBI 如果只完成评估，必须记录为什么不进入本阶段闭环，以及后续专项入口。

## 6. Web 本地内容策略

Web 不假装拥有原生路径。

可选策略：

- 上传后临时阅读。
- 上传后写入浏览器可持久存储，需单独评估容量和可靠性。
- 不支持长期托管文件时，展示禁用说明。
- Web 本地图书不与 Native 托管路径混用。

任务：

- [ ] 明确 Web 本地图书支持范围。
- [ ] 明确 Web 上传文件大小限制。
- [ ] 明确刷新、关闭浏览器、清缓存后的行为。
- [ ] Web 不支持的格式有清晰禁用文案。
- [ ] Web 能力不污染 Native 文件路径模型。

## 7. 本地解析与阅读器

- [ ] TXT 解析继续支持编码检测和章节规则。
- [ ] EPUB 解析是否进入本阶段实现必须单独评估；未进入时保留移动端既有能力和清晰失败路径。
- [ ] PDF 首次提取和分页是否进入本阶段实现必须单独评估；未进入时不得影响在线阅读和 TXT 闭环。
- [ ] MOBI 解析失败路径可解释，不把解析失败伪装成导入成功。
- [ ] 本地章节索引和正文缓存按存储规范落位。
- [ ] 阅读器按内容模式展示可用能力。
- [ ] Android / iOS 阅读器本地书入口、目录、进度保存不回退。
- [ ] 不支持模式不展示不可点击入口。

## 8. 缓存治理落地

关联文档：[缓存治理优化计划](cache_governance_optimization_plan_2026-06-02.md)

任务：

- [ ] 启动首帧后异步触发缓存治理。
- [ ] 6 小时节流，避免频繁扫描。
- [ ] 正文 DB 缓存按条数、体积、TTL 清理。
- [ ] 分页磁盘缓存按条数、体积、TTL 清理。
- [ ] 封面磁盘缓存纳入统一治理。
- [ ] 正文内存缓存改为 LRU + TTL。
- [ ] 手动缓存清理入口说明只删除可重建缓存。
- [ ] 清理失败只记录日志，不影响业务。
- [ ] 清理逻辑不得删除书架、阅读进度、书签、主题资源、用户上传文件或会话凭证。

## 9. 资源能力边界

资源范围：

- 封面。
- 阅读器背景。
- 高级主题资源。
- 字体。
- 启动图。
- 底部导航图标。

任务：

- [ ] 资源能力先分为用户资产、可重建缓存、内置默认资源三类。
- [ ] 资源导入统一走 image / file selection service。
- [ ] Android / iOS 相册 / 文件选择和权限失败文案清楚。
- [ ] Native 资源写入托管文件目录。
- [ ] Web 资源持久化策略单独定义。
- [ ] 资源缺失有占位和恢复路径。
- [ ] 资源删除只删除用户明确选择的受管资源，不删除内置资源或其他平台仍在引用的文件。
- [ ] 资源导出、导入、删除如果未进入本阶段完整实现，必须记录入口降级方式和后续专项。
- [ ] 高级主题资源引用不使用绝对路径直连页面。

## 10. 诊断、日志与清理

- [ ] 诊断导出按平台 adapter 实现。
- [ ] Android / iOS 使用系统分享、保存到可访问位置或 Files 入口。
- [ ] Web 使用下载或复制方式。
- [ ] Desktop 使用保存文件或打开目录方式。
- [ ] 日志恢复失败不影响启动。
- [ ] 缓存清理、诊断导出、文件打开都通过 capability 展示。
- [ ] 日志、诊断导出必须脱敏，不包含 token、cookie、密码、本机路径、URL query / fragment、设备指纹或用户正文内容。

## 11. 本地 override 依赖治理

当前需要重点说明的本地 override 类型：

- PDF 引擎 / 文本抽取。
- 字符集检测。
- 翻页组件。
- Web stub。

任务：

- [ ] 建立 override 清单：包名、原因、改动点、影响平台。
- [ ] 判断是否有成熟上游替代。
- [ ] 判断是否影响 Android / iOS。
- [ ] 判断是否影响 Web JS / Web WASM。
- [ ] 判断是否影响 macOS / Windows / Linux。
- [ ] 为高风险 override 增加最小回归测试。
- [ ] 能回主线的逐步回主线。

## 13. 风险

- [ ] Web 持久化能力和 Native 文件系统差异很大，不能混用语义。
- [ ] PDF / EPUB / MOBI 解析可能引入长任务卡顿。
- [ ] 字符集检测和本地 override 可能影响 Windows / Linux。
- [ ] 缓存清理如果边界不清，可能误删用户资产。
- [ ] 字体和主题资源跨端路径恢复风险高。
- [ ] Android / iOS 权限和文件访问模型变化会放大回归成本。
