## 问题背景

### 当前用户反馈的问题

1. **覆盖安装后功能异常**
   - 用户修改了阅读器设置后覆盖安装，导致应用不好使
   - 删除重装就正常了
   - 说明：旧配置数据与新版本不兼容

2. **覆盖安装多次后性能下降**
   - 用户多次覆盖安装后，应用变卡
   - 重新安装后流畅
   - 说明：脏数据、缓存垃圾积累

3. **删除后重装仍保留登录状态**
   - 用户删除 APP 后重装，发现自动登录
   - 说明：某些数据未被正确清除

### 根本原因分析

- ❌ 缺少启动时的数据版本检查和修复机制
- ❌ 缺少数据迁移失败的降级方案
- ❌ 缓存和脏数据无自动清理
- ❌ 敏感数据未完全清除
- ❌ 配置数据格式变化无兼容处理

## 改造目标

1. **保证覆盖安装后功能正常** - 数据兼容性
2. **保证覆盖安装后性能稳定** - 自动清理脏数据
3. **保证删除后数据完全清除** - 隐私安全
4. **提供用户自救入口** - 降级清理选项

## 阶段 1：紧急修复（1周，P0）

### 目标：解决当前用户反馈的核心问题

### 任务清单

#### 1.1 修复删除后登录状态残留

- [x] **排查登录凭证存储位置**
  - 检查 SharedPreferences 中是否存储了 token
  - 检查 flutter_secure_storage 的清除逻辑
  - 文件：`lib/features/auth/application/auth_service.dart`
  - 结果：移动端主凭证走 `flutter_secure_storage`，展示缓存走 SharedPreferences；旧版 `auth.* token` 仍保留 legacy 迁移读取

- [x] **确保登出时清除所有凭证**
  - 清除 SharedPreferences 中的 `auth.*` 所有 key
  - 清除 flutter_secure_storage 中的所有 token
  - 验证：登出后手动检查存储内容
  - 文件：`lib/features/auth/application/auth_service.dart`
  - 当前进度：登出 / clear 已覆盖 secure secrets + display cache；同时新增 fresh install 自恢复，处理移动端重装后 keychain 残留

- [x] **添加启动时凭证有效性检查**
  - 如果 token 过期或无效，自动清除并跳转登录
  - 避免使用失效凭证导致异常
  - 文件：`lib/app/startup/app_startup_coordinator.dart`

#### 1.2 添加"重置应用"入口

- [x] **添加"重置应用数据"功能**
  - 位置：设置 → 系统 → 重置应用数据
  - 功能：清除所有 SharedPreferences、删除数据库、清除缓存
  - 保留：用户资产文件（本地图书、自定义封面等）
  - 文件：新建 `lib/features/mine/application/app_reset_service.dart`

- [x] **添加二次确认对话框**
  - 明确告知：会清除设置和阅读记录
  - 不会删除：本地图书文件
  - 需要输入确认文字："重置"
  - 文件：`lib/features/mine/presentation/system_settings_page.dart`

- [x] **重置后自动重启应用**
  - 使用 `Restart.restartApp()` 或等价方式
  - 确保重置立即生效

#### 1.3 添加启动时数据健康检查

- [x] **检查数据库完整性**
  - 启动时尝试打开数据库
  - 如果损坏，提示用户"数据库损坏，是否重置？"
  - 备份损坏的数据库文件（用于分析）
  - 文件：`lib/data/datasources/local/app_database.dart`
  - 当前进度：已实现启动期 quick check、损坏数据库备份并重建；显式用户提示仍待补齐

- [x] **检查配置数据格式**

## 风险评估

### 高风险项

1. **数据库迁移失败** - 可能导致数据丢失
   - 缓解：迁移前备份，失败时回滚
   - 测试：多版本升级路径测试

2. **重置功能误操作** - 用户可能误点
   - 缓解：二次确认 + 输入确认文字
   - 测试：UI 测试确保提示清晰

3. **自动清理删除重要数据** - 逻辑错误
   - 缓解：只清理明确的缓存，用户资产不自动删
   - 测试：详细的清理逻辑单元测试

### 中风险项

1. **兼容性问题** - 新逻辑可能与旧版本冲突
   - 缓解：保留旧 key 兼容读取
   - 测试：多版本交叉测试

2. **性能影响** - 启动时清理可能变慢
   - 缓解：后台异步执行，不阻塞启动
   - 测试：启动性能测试
