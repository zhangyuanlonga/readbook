# 书源列表性能与搜索规划（大规模导入）

目标：支持 3000~5000 条书源时仍保持首开可用、滚动顺滑、检索高效。

## P0（已执行）

- [x] SLP-01 列表渲染虚拟化
  - 将书源列表改为 `ListView.builder`，避免一次性构建全部卡片。
  - 验收：滚动时只创建可见项，明显降低卡顿风险。

- [x] SLP-02 书源搜索入口
  - 书源页新增搜索框，支持按名称/域名/分组/备注筛选。
  - 验收：输入关键词后可快速过滤结果，空结果状态提示清晰。

- [x] SLP-03 搜索防抖
  - 搜索输入增加 280ms debounce，减少无效重建。
  - 验收：连续输入时不会每个字符触发重过滤。

- [x] SLP-04 轻量列表流
  - 新增 `watchSourceListItems()`，只读取列表必要字段。
  - 验收：首开不再解析 `rulesJson/rawJson` 等重字段。

## P1（下一步建议）

- [x] SLP-05 分页查询（数据库）
  - 增加 `LIMIT/OFFSET` 查询与总数统计接口。
  - 验收：首次只加载第一页（如 100 条），后续按需加载。

- [x] SLP-06 搜索下推到数据库
  - 将关键词过滤从内存迁移到 SQL（`LIKE`/索引）。
  - 验收：5000 条数据下搜索延迟进一步下降。

## P2（可选增强）

- [ ] SLP-08 导入后增量刷新策略
  - 导入完成后局部刷新，减少全量重建。

- [ ] SLP-09 批量连通性测试队列化
  - 并发受控（2~4）并支持中断，避免 UI 抖动。

- [ ] SLP-10 书源数据分区/归档
  - 对长期停用书源支持归档，减少常用列表压力。
