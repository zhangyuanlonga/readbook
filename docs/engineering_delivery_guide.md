# 工程交付指南

更新时间：2026-03-25
用途：统一书源列表性能、Android 发布和移动端后端集成约定。

## 1. 书源列表性能

目标：支持 3000 到 5000 条书源时仍保持首开可用、滚动顺滑、检索高效。

当前已完成：

- 列表虚拟化
- 搜索入口
- 输入防抖
- 轻量列表流
- 数据库分页
- 搜索下推到数据库

可继续推进：

- 导入后增量刷新
- 批量连通性测试队列化
- 长期停用书源归档

## 2. Android 发布口径

当前统一口径：

- 默认面向手动分发时产出 `arm64` APK
- `universal APK` 只在确实需要单包兼容更多架构时使用
- 若目标是上架商店，优先产出 `AAB`

关键结论：

- APK 体积突然变大，优先检查是否打成 `universal APK`
- 当前 release 构建实际经过 R8

默认直接发用户安装：

```bash
./scripts/build_unified_artifacts.sh android release
```

## 3. 后端移动端集成

当前客户端遵循的后端约定：

- 响应统一使用 envelope
- 鉴权统一使用 `Bearer Token`
- 时间统一使用 UTC RFC3339
- 本地持久化安装和会话相关标识

推荐接入顺序：

1. 设备心跳
2. 登录或注册
3. 持久化 token 后补充设备和访问上报
4. 拉取当前用户
5. 拉取公告和版本更新

## 4. 工程交付最小检查

每次涉及上述主题的改动，至少执行：

```bash
flutter analyze
flutter test
```

## 5. 维护规则

- 书源列表性能、Android 发布、后端移动端集成统一更新本文件。
- 不再为这些主题继续保留单独说明文档。
