# 高级主题颜色体系重构开发计划

更新时间：2026-05-07  
适用范围：`advanced theme` 颜色字段重分类、运行态 token 收口、编辑器重构、兼容迁移  
关联文档：

- `docs/advanced_theme_color_reclassification_plan_2026-05-07.md`
- `docs/advanced_theme_feature_finalization_plan.md`

---

## 1. 目标

把当前“19 个颜色项 + 若干壁纸参数”的高级主题配置体系，重构为更清晰、可维护、可渐进迁移的模型：

- 普通用户只需要调整少量核心颜色
- 高级微调字段收口到折叠层
- 强度相关参数从颜色项中拆出，改成百分比/滑杆项
- 自动推导逻辑统一进入 token 解析层
- 保证旧主题可兼容，避免已有主题失效

---

## 2. 执行原则

- 每完成一项任务，直接在本文件对应任务前打勾
- 每完成一个阶段，补充阶段结果说明

- 不允许先删旧字段、后补兼容
- 所有阶段都必须保持 `flutter analyze` 可通过

## 3. 阶段总览

### 阶段 1：模型与映射收口

目标：先把颜色字段的语义边界和新旧映射关系固定下来，不急着改 UI。

- [ ] 1.1 固定“保留 / 合并 / 自动推导 / 强度滑杆”四类字段清单
- [ ] 1.2 输出旧字段到新语义模型的映射表
- [ ] 1.3 明确哪些字段仍保留在序列化结构中，哪些仅作为运行态推导值
- [ ] 1.4 明确普通层 / 高级层 / 强度层的编辑器展示范围
- [ ] 1.5 明确壁纸层参数与颜色层参数的边界，避免再次混杂

阶段结果：

- [ ] 已形成正式字段分类表
- [ ] 已形成新旧兼容映射表
- [ ] 已确认产品和开发对字段分层口径一致

### 阶段 2：运行态 Token 收口

目标：把自动推导逻辑统一集中到 token 解析层，减少页面自行推导。

- [ ] 2.1 为 `ResolvedAdvancedThemePalette` 增加“推导字段”和“显式字段”的清晰边界
- [ ] 2.2 把 `buttonText` 收口为默认自动推导逻辑
- [ ] 2.3 把 `iconBackground` 收口为默认自动推导逻辑
- [ ] 2.4 把 `cardText` 收口为默认自动推导逻辑，并保留高级覆盖入口
- [ ] 2.5 把 `secondary` 收口为默认从 `primary` 派生，并保留高级覆盖入口
- [ ] 2.6 把 `searchFieldBackground / elevatedSurface / cardBorder` 改成“默认派生 + 可选高级覆盖”
- [ ] 2.7 整理 `textSecondary`、`shadow`、`wallpaperOverlay` 相关的默认强度逻辑
- [ ] 2.8 为 token 层补充测试，验证亮色/暗色、显式覆盖、自动推导三种路径

阶段结果：

- [ ] 页面层不再散落颜色推导逻辑
- [ ] 关键派生字段已收口到 token 层
- [ ] token 解析测试已补齐

### 阶段 3：数据模型与兼容结构调整

目标：在不破坏旧主题的前提下，为新模型增加承载结构。

- [ ] 3.1 为 `AppAdvancedThemeColors` 增加新结构承载能力
- [ ] 3.2 明确旧字段序列化保留策略
- [ ] 3.3 增加读取兼容层：旧主题仍可解析为新运行态模型
- [ ] 3.4 增加保存策略：新主题按新结构写入，同时保留必要兼容字段
- [ ] 3.5 为导入主题兼容路径补充字段映射
- [ ] 3.6 为复制主题、导出主题补充结构一致性校验

阶段结果：

- [ ] 新旧主题都可正常加载
- [ ] 新主题不会再强依赖旧字段结构
- [ ] 导入/导出/复制链路可跑通

### 阶段 4：编辑器 UI 重构

目标：把高级主题编辑页从“平铺一长串颜色项”改成分层可理解的结构。

- [ ] 4.1 重构普通层，只保留核心风格颜色
- [ ] 4.2 重构高级层，把组件级微调字段折叠到高级配置区
- [ ] 4.3 新增强度层，把透明度/模糊/强弱控制项集中到滑杆区
- [ ] 4.4 移除不该再直接暴露的独立颜色项入口
- [ ] 4.5 调整预览区，确保能体现普通层、高级层、强度层的区别
- [ ] 4.6 调整字段顺序，让最常用配置项优先进入首屏
- [ ] 4.7 统一编辑器内所有颜色项的尺寸、间距、输入框密度

阶段结果：

- [ ] 首屏只显示核心风格颜色
- [ ] 高级微调与强度控制分区明确
- [ ] 编辑器首屏信息密度明显下降

### 阶段 5：迁移与兼容验证

目标：验证旧主题、现有用户数据和外部导入不会因为重构出问题。

- [ ] 5.1 抽样验证现有本地主题在重构后加载结果不变
- [ ] 5.2 验证老主题进入编辑页后不会丢字段
- [ ] 5.3 验证保存一次后不会错误清空旧主题视觉效果
- [ ] 5.4 验证导入 JSON / ZIP / RED / RGSHARE 的颜色映射合理
- [ ] 5.5 验证不同主题数量下的列表读取和编辑页打开性能
- [ ] 5.6 补充回归测试和 smoke

阶段结果：

- [ ] 旧数据兼容通过
- [ ] 导入兼容通过
- [ ] 列表与编辑页性能回归通过

### 阶段 6：清理与最终收口

- [ ] 6.5 更新测试基线和后续扩展规范

## 5. 关键设计决策记录

### 5.1 为什么要减少直接暴露的颜色项

- [ ] 确认“减少暴露项”是为了降低复杂度，不是为了减少能力
- [ ] 确认高级微调仍然保留，只是位置后移

### 5.2 为什么要把部分字段改成自动推导

- [ ] 确认 `buttonText` 首要是可读性问题，不应该让用户随意配
- [ ] 确认 `iconBackground` 首要是辅助承托层，不应独立成为主风格项
- [ ] 确认 `cardText` 更偏可读性，应优先自动推导

### 5.3 为什么要引入强度层

- [ ] 确认阴影、次级文字、壁纸遮罩本质是强弱问题，不是色相问题
- [ ] 确认把“颜色”和“强度”拆开后，编辑器认知成本更低

- [ ] 普通用户进入编辑页首屏能理解每个字段在改什么

- [ ] 强度层与颜色层区分明显

### 6.2 工程实现

- [ ] token 推导逻辑集中，不再散落页面层

- [ ] 旧主题显示效果不明显回退
- [ ] 新主题保存后不会写出错误结构
- [ ] 导入主题结果符合预期
