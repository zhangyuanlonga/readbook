## 3. 阅读字数统计口径（建议作为当前默认）

### 3.1 不参考 MD3 的字段语义

MD3 中的 `words / readWords` 实际上混入了章节索引语义，不适合作为“真实阅读字数”定义。  
当前 Flutter 项目应继续使用独立口径，不与 MD3 对齐命名含义。

### 3.2 主口径定义

主口径名称继续使用“阅读字数”，但其含义明确为：

- 只统计正文文本章节
- 基于清洗后正文文本长度估算
- 不统计图片流、封面、章节标题栏、页眉页脚、控制区
- 不统计漫画章节到主字数口径

### 3.3 单次会话统计规则

单次会话字数建议定义为：

- `sessionReadChars = max(0, endRatio - startRatio) * chapterTextLength`
- 结果四舍五入后取整
- 上限为当前章节文本长度
- 如果章节没有可统计文本，则记为 `0`

这意味着：

- 向前阅读会累计字数
- 倒退回看不累计新增字数
- 同一会话内来回快速拖动，不按绝对位移累计

### 3.4 跨会话规则

当前阶段先采用“按提交会话累加”的简单规则：

- 会话之间不做全局去重
- 同一章节隔天再次阅读，如果仍有明显向前阅读，允许再次累计
- 先保证口径稳定，再评估是否需要“重复阅读去重”

### 3.5 跳章 / 分页 / 漫画规则

- 跳章：
  - 切章前先提交上一章会话
  - 新章节重新开始会话
- 滚动模式与分页模式：
  - 统一使用章节进度比例估算
  - 不额外拆两套公式
- 漫画章节：
  - 不进入主“阅读字数”口径
  - 继续参与时长、会话数、触达章节数
  - 如果未来确实需要漫画统计，单独设计“阅读页数 / 图片数”口径

### 3.6 当前实现约束

当前阅读页实现基于 `_chapterTextLength()` 和会话起止进度比例估算。  
其中 `_chapterTextLength()` 统计的是清洗后的正文文本长度，当前已调整为：

- 只记向前增量，不再把倒退阅读按新增字数累计
- 漫画章节直接记为 `0`，不进入主“阅读字数”口径

## 4. 章节维度统计最小决策稿

### 当前结论

当前周期不做独立“章节维度统计页”，先保留摘要卡里的“触达章节数”指标。  
这一结论已经作为当前执行口径采用。

### 原因

- 阅读记录主链路刚稳定，仍在做基线验证
- 字数统计口径还在继续校准
- 独立章节页会引入新的页面结构、筛选、排序和跳转设计
- 现在就做，返工概率高于收益

### 当前保留方案

- 保留摘要卡“触达章节数”
- 时间线继续展示章节标题
- 合并记录继续保留章节定位信息

### 何时重开章节页讨论

满足以下条件后再重开：

- 第 1 组基线验证完成
- 第 2 组字数统计口径稳定
- 有明确产品目标，不只是“信息更多”

### 如果必须做独立页面，建议最小范围

只做单书维度，不做全局排行榜页。  
第一页最小能力建议为：

- 某本书的触达章节数
- 最近触达章节列表
- 章节触达顺序或最近阅读时间

不建议当前阶段直接做：

- 全站章节排行榜
- 跨书章节明细总表
- 基于章节的复杂留存分析

## 5. 本轮结论

当前最合理的执行顺序仍然是：

1. 先完成第 1 组手动基线验证
2. 再继续收敛第 2 组字数口径误差
3. 第 7 组先按“不做独立页”推进，避免返工
