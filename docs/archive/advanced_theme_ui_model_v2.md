# 高级主题 UI 外观模型 V2

## 1. 目标

高级主题不再以“底层设计 token 编辑器”为目标，而是改成面向用户可理解的“结果层外观配置”。

核心原则：

- 用户优先看到的是最终效果相关项，而不是技术名词
- 资源主轴优先：背景图、封面图集、底栏图集
- 颜色项保持少量且按业务分组展示
- 复杂项可以存在，但默认折叠到高级颜色

## 2. 我们项目自己的 UI 结构

结合当前代码和页面结构，我们项目的外观主要由以下几层组成。

### 2.1 页面层

作用范围：

- 书架、发现、我的页面的大面积背景
- 页面级文字
- 输入区和分隔区域

建议暴露项：

- 强调色
- 页面背景
- 次级背景
- 主要文字
- 辅助文字
- 边框

### 2.2 卡片层

作用范围：

- 书架卡片
- 发现卡片
- 我的页功能卡
- 弹窗和信息面板

建议暴露项：

- 卡片背景
- 卡片文字
- 卡片边框
- 阴影强度

备注：

- 当前 `卡片文字` 已开始独立字段化，并接入主页面卡片标题
- 当前 `阴影强度` 暂时仍由颜色近似表达

### 2.3 搜索与输入层

作用范围：

- 书架搜索框
- 搜索页输入区域
- 其他表单输入框

建议暴露项：

- 搜索框背景
- 输入框背景
- 输入框边框

备注：

- `搜索框背景` 已拆成独立字段
- 输入框背景 / 输入框边框仍暂时复用现有字段

### 2.4 选项与标签层

作用范围：

- 选项卡
- 筛选 chip
- 标签 pill
- 元信息 chip

建议暴露项：

- 选项卡背景
- 选项卡边框
- 标签背景
- 标签文字

备注：

- 当前阶段先使用 `primaryContainer` 和 `cardBorder`
- 后续可拆分 `标签背景/文字`

### 2.5 状态反馈层

作用范围：

- 提示卡片
- 警告/错误/信息反馈
- 状态 badge

建议暴露项：

- 提示强调
- 提示底色

### 2.6 底栏层

作用范围：

- 标准底部导航栏
- iOS 风格 dock 导航

当前策略：

- 底栏图集

明确不做：

- 底栏背景图
- 底栏单独颜色编辑项

说明：

- 底栏背景、边框、图标/标签颜色由高级主题 palette 自动联动
- 用户只配置底栏图集，不再继续细分底栏颜色

### 2.7 资源主轴

用户最直观感知主题风格的 3 个主入口：

- 背景图
- 封面图集
- 底栏图集

## 3. 当前字段映射

当前高级主题仍基于现有字段存储，编辑页先按“结果层”重新命名和分组。

| 结果层配置 | 当前字段 |
|---|---|
| 强调色 | `primary` |
| 页面背景 | `background` |
| 次级背景 | `surface` |
| 主要文字 | `textPrimary` |
| 辅助文字 | `textSecondary` |
| 边框 | `outline` |
| 卡片背景 | `card` |
| 卡片边框 | `cardBorder` |
| 选项卡背景 | `primaryContainer` |
| 提示强调 | `noticeAccent` |
| 提示底色 | `noticeSurface` |
| 高层级背景 | `elevatedSurface` |
| 图标底色 | `iconBackground` |
| 按钮文字 | `buttonText` |
| 阴影 | `shadow` |

## 4. 当前实现状态

### 已完成

- 编辑页默认按业务分组展示，而不是直接暴露所有底层 token
- 书架、发现、我的页面已接入高级主题运行态壁纸
- 封面图集 fallback 已覆盖主链路和若干补充页面
- 底栏背景和图标视觉已与高级主题 palette 联动

### 暂未独立支持

- 卡片背景模糊
- 输入框边框
- 标签背景
- 标签文字

这些当前先通过已有字段联动表达，后续按优先级逐步拆成独立字段。

## 5. 后续建议顺序

### 第一阶段：先把表达方式做对

- 保持用户看到的是“页面 / 卡片 / 搜索框 / 选项卡 / 高级颜色”
- 继续减少技术名词暴露

### 第二阶段：补真正需要独立的字段

- 输入框边框
- 卡片边框

### 第三阶段：效果类能力

- 卡片背景模糊
- 更细的标签 / 选项卡视觉控制

## 6. 结论

高级主题后续不应再朝“设计系统调试面板”方向扩展，而应坚持：

- 资源主轴：背景图 / 封面图集 / 底栏图集
- 少量结果层颜色
- 逐步补少数真正有价值的独立项

这更符合我们当前产品的 UI 结构，也更符合普通用户的理解方式。
