# 高级主题开发任务

## 1. 目标

把“高级主题”从“可创建 / 可编辑”推进到“可应用且不和主题颜色冲突”。

核心规则：

- `主题颜色` 负责基础主题。
- `高级主题` 只覆盖已配置项。
- 未配置字段继续回退到基础主题。
- `高级主题` 的应用入口放在高级主题列表。
- 外观页只显示当前状态摘要，不承担真正的切换操作。

## 2. 当前设计结论

### 2.1 主题关系

- `seedColor / ThemeMode` 继续作为全局基础主题来源。
- 高级主题不是替代基础主题，而是在其之上的覆盖层。
- 最终主题解析顺序为：
  1. 先根据 `seedColor` 生成基础 `ColorScheme`
  2. 再用高级主题已配置字段覆盖

### 2.2 生效方式

- 高级主题在编辑页中只是模板，不自动全局生效。
- 全局同一时间只允许一个高级主题生效。
- 通过 `activeAdvancedThemeId` 表示当前生效主题。
- `activeAdvancedThemeId == null` 表示未启用高级主题。

### 2.3 页面职责

- 高级主题编辑页：
  - 负责创建、编辑、预览
  - 不负责“自动应用”
- 高级主题列表页：
  - 负责应用、停用、当前生效标记
- 外观页：
  - 只显示当前高级主题状态摘要
  - 点击进入高级主题列表

## 3. 当前已具备能力

- 高级主题双模式配置：浅色 / 深色
- 颜色字段：
  - 强调色
  - 辅助强调
  - 提示强调
  - 提示底色
  - 页面背景
  - 次级背景
  - 高层级背景
  - 卡片背景
  - 卡片边框
  - 图标底色
  - 主要文字
  - 辅助文字
  - 按钮文字
  - 边框
  - 阴影
  - 壁纸遮罩色
- 壁纸能力：
  - 绑定当前高级主题壁纸
  - 壁纸遮罩强度
  - 从背景库底部弹层中选择并应用
- 底栏能力：
  - 高级主题可记录 `bottomNavGalleryId`
  - 编辑页可底部弹层选择底栏图集

## 4. 待开发任务

### 4.1 状态与持久化

1. 新增 `activeAdvancedThemeId` 的持久化存储。
2. 新增当前生效高级主题 Provider。
3. 新增“高级主题是否启用”的统一读取入口。

### 4.2 主题解析层

4. 新增统一主题解析层：
   - 输入：基础主题 + 高级主题
   - 输出：最终 UI 使用的解析后主题 token
5. 明确优先级：
   - 高级主题已配置字段优先
   - 未配置字段回退到基础主题
6. 不直接推翻现有 `ColorScheme` 生成逻辑，而是在其上做覆盖。

### 4.3 列表页与外观页

7. 在高级主题列表页增加：
   - `应用`
   - `停用高级主题`
   - `当前生效` 标记
8. 外观页增加高级主题状态摘要：
   - `未启用`
   - 或 `当前：主题名称`
9. 外观页不提供直接切换，只跳转到高级主题列表。

### 4.4 页面接入顺序

10. 第一阶段先接入 `我的页`：
   - 小卡片背景
   - 图标圆底
   - 卡片
   - 提示块
   - 背景层级
11. 第二阶段接入 `发现页`
12. 第三阶段接入 `书架页`
13. 阅读器正文页暂不接入，保持独立设置体系。

### 4.5 资源联动

14. 壁纸生效：
   - 应用于外层页面背景
   - 结合遮罩色和遮罩强度一起渲染
15. 底栏图集生效：
   - 若高级主题配置了 `bottomNavGalleryId`，则应用时切换到底栏图集
   - 若未配置，则沿用当前全局底栏图集
16. 封面暂不纳入应用态：
   - 当前项目缺少真正的“封面样式配置源”
   - 后续如补充配置源，再接入高级主题绑定

### 4.6 编辑器增强

17. 编辑当前生效主题时，保存后应即时刷新相关页面。
18. 增加“一键由浅色生成深色”。
19. 增加“从当前主题颜色回填”优化。
20. 增加基础对比度检查：
   - 主要文字 vs 背景
   - 按钮文字 vs 强调色
   - 提示文字 vs 提示底色

## 5. 推荐开发顺序

### 第一阶段

1. `activeAdvancedThemeId`
2. 当前生效高级主题 Provider
3. 统一主题解析层
4. 高级主题列表页的 `应用 / 停用 / 当前生效`
5. 外观页状态摘要

### 第二阶段

6. 我的页接入高级主题解析结果
7. 壁纸遮罩生效
8. 图标底色生效
9. 提示色与高层级背景生效

### 第三阶段

10. 发现页接入
11. 书架页接入
12. 底栏图集联动生效

### 第四阶段

13. 一键生成深色
14. 自动补全文字 / 按钮文字颜色
15. 对比度检查

## 6. 验收标准

- 未启用高级主题时，应用行为与现在完全一致。
- 启用高级主题后，仅覆盖已配置字段。
- 未配置字段仍然跟随基础主题颜色。
- 高级主题列表页可明确显示：
  - 当前生效
  - 应用
  - 停用高级主题
- 外观页只显示摘要，不与列表页操作重复。
- 我的页小卡片图标圆底可被 `图标底色` 独立控制。
- 提示块可被 `提示强调 / 提示底色` 明确控制。
- 壁纸遮罩色与强度在预览和真实页面上都可见差异。
- `flutter analyze` 通过。

## 7. 暂不做事项

- 阅读器正文页接入高级主题
- 成功 / 警告 / 错误状态色
- 封面样式应用态绑定
- 过度细拆的颜色项：
  - 主按钮背景
  - 主按钮描边
  - 卡片标题色
  - 卡片副标题色
  - 容器文字色

## 8. 用户体验原则

- 高级主题是“进阶增强”，不是“专业调色台”。
- 用户应先能快速做出一个像样主题，再决定要不要细调。
- 默认流程必须短，复杂能力只能渐进展开。
- 未配置字段自动继承基础主题，避免用户必须填满所有项。
- 能自动推导的颜色尽量自动推导，不强迫手配。
- 同一类操作只保留一个主入口，避免多处切换造成困惑。
- 预览必须即时、直观，避免用户改了看不懂变化。
- 高级主题的“应用”与“编辑”分离，避免误操作导致全局突然变化。

### 8.1 交互约束

- 基础色项优先显示，次要色项靠后。
- 一屏优先看到：
  - 主题名
  - 浅色 / 深色切换
  - 关键颜色
  - 预览
- 壁纸、底栏这类资源型项，优先使用“选择并应用”的简单动作，不做复杂配置链。
- 列表页负责“应用”，编辑页负责“修改”，角色保持清晰。
- 后续若继续增加字段，优先考虑折叠到“更多设置”，不要全部平铺。

### 8.2 开发约束

- 不无节制增加字段，新增字段必须有明确视觉收益。
- 新增字段必须同时考虑：
  - 默认值
  - 自动回退
  - 预览可感知
- 若某字段用户难以理解，优先改命名和分组，而不是增加说明文字。
- 若某能力会增加明显学习成本，优先做成可选增强，不进入默认主流程。
