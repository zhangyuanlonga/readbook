# 阅读器改造落地计划

更新时间：2026-04-02  
用途：将当前阅读器从“多套阅读实现并存”收口为“统一文本阅读内核 + 多渲染委托 + 漫画独立路径”的可执行任务清单。

最终目标补充说明：

- **完整具备 `MD3` 阅读器这块应该有的配置项**
- **结构收口是为了更完整、更稳定地承载这些配置项，不是为了减少能力**
- **后续验收标准之一，就是 `MD3` 目标配置能力没有缺口**

## 1. 当前判断

当前阅读器的主要问题不是功能不够，而是结构分叉过深：

- 文本分页、文本滚动、漫画阅读已经变成 3 条阅读链路
- 分页和滚动不只是动画不同，而是内容组织、进度、信息栏、部分交互都已分叉
- 设置项过重，常用项和高级项没有充分分层
- 小说阅读与漫画阅读共用一个页面壳，但产品语义并不完全一致

对标 `legado` 这类成熟阅读器，可借鉴的核心不是“少功能”，而是：

- 同一个文本阅读内核
- 同一个章节/进度模型
- 通过不同委托切换翻页方式
- 常用设置轻量暴露，高级设置下沉

## 2. 改造目标

本轮改造统一按以下目标执行：

- 文本阅读只保留一套内容内核
- 滚动、分页、翻页动画只作为文本阅读的渲染委托存在
- 漫画阅读继续独立，但与文本阅读共享尽量少的业务壳
- 设置入口分层，首层只保留高频项
- 目录、书签、进度、自动阅读、换章等行为在分页和滚动下保持一致
- 完整承接 `MD3` 阅读排版与阅读设置能力，不因结构收口而删功能

## 3. 明确边界

本轮要做：

- 统一文本内容模型
- 统一文本阅读状态模型
- 收口分页/滚动实现
- 收口阅读菜单和设置分层
- 修正分卷、正文插图、进度定位等体验问题

本轮不做：

- 不强行把漫画阅读并入文本阅读内核
- 不先做大规模视觉重设计
- 不为了统一结构而打断当前缓存、书签、阅读记录兼容

## 4. 影响范围

预计重点涉及：

- `lib/features/reader/presentation/reader_page.dart`
- `lib/features/reader/application/chapter_content_service.dart`
- `lib/domain/entities/reader_settings.dart`
- `lib/domain/entities/chapter.dart`
- `lib/features/book/presentation/book_detail_page.dart`
- `lib/features/book/presentation/widgets/book_detail_sections.dart`

如果后续拆文件，优先把阅读器核心状态、文档模型、渲染委托从 `reader_page.dart` 中分离。

## 5. 任务清单

### 阶段 A：先统一口径和约束

- [x] 确认文本阅读目标架构为“统一文本内核 + 滚动/分页委托”，不再接受分页和滚动各自维护正文状态
- [x] 确认漫画阅读仍保留独立路径，不纳入本轮文本内核合并范围
- [x] 确认正文插图进入统一正文顺序，不再走独立 `images[]` 语义
- [x] 确认分页模式遇到正文插图时的第一阶段策略
  结论：保持统一内容模型；如果分页渲染暂时无法完整承载正文插图，则只允许在同一文本内核下做局部降级渲染，不允许切回另一套文本业务链路
- [x] 确认文本阅读的唯一进度主键
  结论：以 `chapterIndex + chapterPosition` 作为主进度键，`chapterUrl/chapterId` 仅作为定位辅助和兼容字段
- [x] 确认阅读页首层菜单只保留高频项，缓存、换源、详情、书架降到二级入口
- [x] 确认 `MD3` 已实现到一半的阅读排版能力不删减
  至少保留：字距、行距、段距、缩进、正文边距、章节头位置、信息栏显示项与位置语义

### 阶段 A 已确认决议

- 文本阅读后续统一收口为“一个文本内容内核 + 多个渲染委托”
- 文本滚动和文本分页的差异只允许存在于渲染、动画、可见范围计算和定位策略层
- 漫画阅读继续独立存在，但不再反向影响文本阅读架构
- 正文插图属于文本正文的一部分，顺序必须跟随正文文档本身
- `images[]` 只保留给纯图片章节或漫画章节，不再承担正文插图语义
- 文本阅读进度统一按章节位置和章内逻辑位置表达，不再按不同模式分别定义
- 阅读器首层交互以阅读主路径为先，书籍运营类动作统一降权

### 阶段 B：补基线和回归保护

- [x] 为当前阅读器补一份“改造前基线”清单
  至少覆盖：打开章节、切章、书签、目录、自动阅读、换源、缓存、分页、滚动、漫画
- [x] 为文本阅读补统一回归用例
  至少覆盖：同一章在滚动/分页下恢复进度一致、切模式不丢章节、切源不丢定位
- [x] 为分卷目录补测试
  至少覆盖：分卷节点不可读、跳章会跳过分卷节点、目录展示与实际行为一致
- [x] 为正文插图补测试
  至少覆盖：正文图片顺序保留、文本前后顺序不乱、非纯图片章节不误判为漫画
- [x] 为阅读设置补最小回归测试
  至少覆盖：主题、字号、翻页模式、自动阅读、信息栏、字体
- [x] 为阅读排版细节补回归用例
  至少覆盖：字距、行距、段距、缩进、正文边距、章节头位置、信息栏显示项/位置

阶段 B 本轮补充说明：

- 已补“同一逻辑位置在分页/滚动渲染下不漂”的应用层测试
- 已补 `ReaderSurfaceMetrics / ReaderLayoutResolver` 的统一口径测试
- 已补字距、行距、正文边距、章节头位置等排版细节的持久化与样式回归测试

### 阶段 C：抽出统一文本内容模型

- [x] 新建文本阅读文档模型
  建议命名：`ReaderDocument / ReaderBlock / ReaderTextBlock / ReaderImageBlock / ReaderTitleBlock`
- [x] 统一把脚本正文、本地正文、清洗后的正文都转换为同一种文档模型
- [x] 将“正文段落数组”从页面临时状态改为文档模型派生结果
- [x] 将正文插图改为文档块的一种，而不是页面旁路字段
- [x] 明确纯图片章节与正文插图章节的区别
  纯图片章节继续走漫画路径；正文插图章节仍属于文本阅读
- [x] 为统一文档模型增加调试输出和最小序列化能力，方便回归和排错

### 阶段 D：抽出统一文本阅读状态模型

- [x] 新建文本阅读会话状态对象
  建议包含：当前章节、逻辑位置、可见位置、阅读模式、是否自动阅读、是否在切章中
- [x] 把分页页号、滚动偏移、当前章节等分散状态收口到统一状态对象
- [x] 定义统一的“逻辑阅读位置”结构
  建议包含：`chapterIndex + blockIndex + offsetInBlock`，必要时补 `pageIndex`
- [x] 统一书签、阅读进度、目录跳转、自动阅读都基于同一逻辑位置
- [x] 统一“上一章/下一章/边界提示/跨章衔接”逻辑，不再由分页和滚动各自处理
- [x] 统一分卷节点跳过逻辑，不允许任何文本阅读链路直接打开 `isVolume`

### 阶段 E：建立文本阅读渲染委托层

- [x] 从 `reader_page.dart` 中抽出文本阅读渲染接口
  建议命名：`TextReaderRenderer` 或 `TextReaderDelegate`
- [x] 实现滚动渲染委托
  负责：滚动视图、可见范围、滚动定位、滚动自动阅读
- [x] 实现分页渲染委托
  负责：分页布局、页切换、页动画、页内定位
- [x] 将当前翻页动画能力全部挂到分页委托上，而不是散落在页面逻辑里
- [x] 将滚动模式从“另一套阅读器”改为“同一文本文档的另一种呈现方式”
- [x] 支持在不重新加载章节内容的前提下切换滚动/分页
- [x] 保证切换模式后仍能定位到同一逻辑阅读位置附近

### 阶段 F：收口阅读页菜单和设置

- [ ] 重做阅读页底部首层入口
  建议保留：目录、进度/定位、主题/界面、阅读设置
- [x] 将缓存、换源、详情、书架从顶栏主操作中降权
  建议收进“更多”或书籍级菜单，而不是阅读主路径
- [x] 将设置拆成“基础设置 + 高级设置”
- [x] 基础设置只保留高频项
  建议：亮度、主题、字号、翻页方式、字体、行距、边距
- [x] 高级设置收纳低频项
  建议：信息栏、自动换源、音量键翻页、背景图、自定义颜色、进阶排版
- [x] 将排版设置按语义分组，而不是按字段堆叠
  建议拆成：正文排版、正文版面、章节头、信息栏、视觉装饰
- [x] 保留现有 `MD3` 阅读排版能力，但收口为 preset + 高级项
  不能因为降复杂度而直接删除字距、段距、缩进、章节头位置等能力
- [ ] 为文本模式补一个主流的进度定位面板
  建议：章节滑杆 + 当前章内进度 + 快速跳转
- [ ] 保证目录、书签、搜索、进度定位都使用同一跳转入口

阶段 F 当前进展说明：

- 已将语义化配置组与 preset 服务接回阅读器设置页
- 现在可以直接手动验证：正文排版、正文版面、章节头、信息栏、字体 preset 是否可用
- 阶段 F 仍未完成的部分：
  底部首层入口重做、主流进度定位面板、目录/书签/搜索/进度定位统一跳转入口

### 阶段 G：目录和分卷体验收口

- [x] 阅读页目录明确区分“分卷节点”和“可读章节节点”
- [x] 分卷节点视觉上与普通章节明显不同
  建议：卷标题样式、禁用箭头、不可点击、可折叠留待后续
- [x] 当前章节定位、目录定位、书签跳转都只指向可读章节
- [x] 目录搜索结果如果命中分卷标题，跳转行为要明确
  建议：定位到该卷首个可读章节，或只高亮不直接进入

### 阶段 H：清理旧分支和重复逻辑

- [x] 删除只服务于旧滚动链路的重复状态字段
- [x] 删除只服务于旧分页链路的重复状态字段
- [x] 删除“因为阅读模式不同而重复写了一遍”的跳章、进度、提示逻辑
- [x] 清理阅读页中过多的模式判断分支
  目标：文本分页/文本滚动只保留委托层分支，业务层不再到处判断
- [x] 将超大文件 `reader_page.dart` 按职责拆分
  建议至少拆出：阅读状态、菜单/设置、文本渲染委托、漫画渲染

### 阶段 I：验收和发布前检查

- [ ] 手工验证文本阅读主路径
  至少覆盖：打开章节、翻页、滚动、切章、目录、书签、自动阅读、切换主题、切换模式
- [ ] 手工验证漫画阅读主路径
  至少覆盖：连续长图、分页图、横向翻页、自动阅读、定位
- [ ] 手工验证异常路径
  至少覆盖：正文为空、章节失效、换源失败、目录缺失、仅分卷无正文
- [ ] 验证同一本书在滚动/分页切换后进度基本一致
- [x] 验证含正文插图章节不会误走漫画模式
- [x] 验证目录分卷节点不会被打开
- [x] 完成 `flutter analyze`
- [x] 完成与阅读器相关的 `flutter test`

## 6. 建议执行顺序

建议严格按下面顺序推进，不要跳步：

1. 先完成阶段 A 到阶段 B，锁定口径和回归保护
2. 再完成阶段 C 到阶段 D，先统一内容和状态
3. 然后完成阶段 E，正式把分页/滚动收口为委托
4. 再完成阶段 F 到阶段 G，做菜单、设置、目录体验收口
5. 最后完成阶段 H 到阶段 I，清旧逻辑并做发布前验证

## 7. 每阶段验收口径

### A-B 完成后

- 口径不再摇摆
- 有最小回归保护
- 后续改造不会边改边失控

### C-D 完成后

- 文本阅读只认一种文档模型
- 文本阅读只认一种进度模型
- 业务逻辑不再依赖“当前是分页还是滚动”

### E 完成后

- 滚动和分页只是渲染差异
- 切模式不需要重建整套业务状态
- 后续加新翻页动画只改委托层

### F-G 完成后

- 阅读页首层更接近主流小说阅读器
- 高级功能仍保留，但不打断主路径
- 目录、分卷、书签、定位体验一致

### H-I 完成后

- 旧分支被清理
- `reader_page.dart` 体量明显下降
- 发布前验证可以稳定重复执行

## 8. 当前建议优先级

如果资源有限，优先做这 6 项：

- [x] 阶段 A 的目标架构确认
- [ ] 阶段 B 的最小回归保护
- [x] 阶段 C 的统一文本文档模型
- [x] 阶段 D 的统一逻辑阅读位置
- [x] 阶段 E 的滚动/分页委托层
- [x] 阶段 F 的菜单与设置分层

完成这 6 项后，阅读器的结构问题就基本从“根上收住了”。
