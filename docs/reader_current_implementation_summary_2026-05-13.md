# 阅读器当前整体实现摘要

日期：2026-05-13

本文用于对外/协作评审，概括当前阅读器功能由什么方案实现，不展开具体代码细节。

## 1. 总体架构

阅读器采用“统一内容模型 + 多视图适配”的架构。

- 在线书、本地图书最终都会转成统一阅读内容。
- 文本、图文、漫画、PDF 等内容先进入内容准备层，再由阅读器根据内容类型和用户设置选择展示方式。
- 滚动阅读和分页阅读是两套独立视图，共享底层内容、阅读进度、书签、主题、字体和缓存。

核心分层：

```text
页面壳层
阅读模式解析
滚动/分页/漫画视图
内容加载与章节预加载
统一文档模型
在线书源 / 本地图书解析
缓存、设置、记录、书签
```

## 2. 内容来源

### 在线书籍

- 通过书源运行时加载书籍详情、目录和章节正文。
- 章节正文加载后会转成统一的章节内容结果。
- 支持章节缓存、换源、搜索命中和在线章节刷新。

### 本地图书

支持多种本地格式，统一接入阅读器：

- TXT
- EPUB
- HTML / Markdown
- PDF
- Kindle 相关格式入口

本地图书通过本地解析器建立书籍索引、目录和章节内容，再交给阅读器展示。

## 3. 统一内容模型

阅读器内部使用统一的文档结构表达正文。

目前支持的内容块包括：

- 普通正文
- 标题
- 列表项
- 引用
- 脚注
- 图片

这样做的目的：

- TXT 可以是纯文本 block。
- EPUB/HTML 可以是图文混排 block。
- 漫画可以是图片 block。
- 后续扩展新格式时，不需要重写阅读器视图。

## 4. 阅读模式

阅读器会根据内容类型和用户设置选择模式。

### 文本分页

- 使用分页视图展示。
- 适合模拟翻书体验。
- 支持点击翻页、滑动翻页和多种翻页动画。
- 分页结果会根据字号、行高、页面尺寸等参数计算。

### 文本滚动

- 使用纵向滚动视图展示。
- 适合连续阅读和快速浏览。
- 按段落/内容块构建列表，不一次性铺完整个超长正文。
- 支持滚动进度保存。

### 漫画/纯图片

- 使用独立漫画视图。
- 支持连续模式、分页模式和横向阅读。
- 图片会按设备和资源预算控制解码尺寸。

### 图文 EPUB

- 使用统一 block 模型。
- 滚动模式直接按图文内容块展示。
- 分页模式会把文字和图片一起纳入分页模型。

### PDF

- 本地 PDF 入口会按页建立可读内容。
- 当前更偏向把 PDF 页作为特殊本地内容接入阅读器，而不是完全独立的 PDF 阅读器。

## 5. 分页实现

分页是独立服务，不和滚动视图混在一起。

当前分页方案：

- 根据章节内容、页面宽高、字号、行高、段距、字体等参数生成分页结果。
- 文本分页使用文本测量计算每页可容纳的字符范围。
- 图文分页使用 block 分页，文字和图片都会占用页面空间。
- 分页过程支持取消，避免切章或改设置后旧结果污染当前页面。
- 分页结果可缓存，第二次打开同章节同设置时可以复用。

## 6. 缓存与预加载

阅读器有多层缓存和预加载。

### 章节缓存

- 在线章节可以缓存，减少重复请求。
- 本地章节从本地索引或文件读取。

### 分页缓存

- 分页结果有内存缓存和磁盘缓存。
- 缓存 key 会包含章节和分页相关设置。
- 设置变化后会触发重新分页。

### 邻章预加载

- 阅读当前章时，会预加载相邻章节内容。
- 分页模式下，也会尝试预热相邻章节分页结果。
- 预加载有失败记忆和资源预算，避免反复拉失败任务。

### 图片缓存与解码预算

- 阅读器会根据设备像素比、内容类型和资源预算计算图片解码尺寸。
- 图片显示时使用 `cacheWidth/cacheHeight` 限制解码开销。
- 全局图片缓存大小会按阅读器预算调整。

## 7. 阅读进度与记录

阅读器保存两类状态：

### 阅读进度

- 记录当前书、章节、章节进度、页码或滚动位置。
- 进度保存使用防抖，不会每次滚动或翻页都立刻写入。
- 页面退出、切章、后台等关键节点会主动 flush。

### 阅读记录

- 记录阅读时长、阅读章节、阅读位置等统计信息。
- 阅读会话会定期提交，避免长时间阅读只在退出时保存。

## 8. 书签与标注

阅读器支持书签和文本标注相关能力。

- 书签基于章节、段落和文本偏移保存。
- 阅读页面可以高亮已有标注范围。
- 文本选择和点击定位通过阅读器内的文本 offset 映射实现。

## 9. 主题、字体和排版

阅读器支持独立阅读设置。

主要包括：

- 字号
- 行高
- 段距
- 页边距
- 字体
- 对齐方式
- 背景色 / 背景图
- 深色/浅色模式
- 高级主题覆盖

字体、字号、页面尺寸等变化会影响分页结果，因此需要重新分页。

## 10. 翻页与交互

文本分页支持：

- 点击翻页
- 滑动翻页
- 点击加滑动
- 仿真翻页
- 平移动画
- 覆盖动画
- 淡入淡出
- 垂直翻页
- 无动画

文本滚动支持：

- 纵向滚动
- 点击滚动
- 自动阅读

漫画支持：

- 连续滚动
- 单页分页
- 横向分页
- 图片缩放和平移

桌面端还支持键盘和鼠标滚轮相关阅读交互。

## 11. 低资源与稳定性策略

当前阅读器已经有一些低资源设计：

- 图片解码预算
- 图片缓存上限
- 章节预加载预算
- 分页缓存预算
- 后台任务 token 取消机制
- 阅读进度防抖保存
- 生命周期切换时保存进度和暂停运行时任务

目标是避免阅读器在长时间阅读、大图章节、漫画或大文件场景下占用过多内存。

## 12. 当前主要待优化方向

当前架构方向整体合理，但还有几块值得继续优化：

1. 本地 TXT/EPUB 首开可以更懒加载，优先目录和当前章，减少全书正文预解析。
2. 分页计算需要更细的性能观测，确认长章节是否存在 UI jank。
3. 流式分页还可以更进一步，做到当前页优先产出，而不是偏整章计算后再分批交付。
4. 图文 EPUB 的分页缓存还可以更完整。
5. 翻页动画期间可进一步降低低优先级预加载和图片任务的抢占。
6. 真机性能矩阵需要补齐，尤其是低端 Android、大 TXT、大 EPUB、漫画长章节。

## 13. 对外评审可重点提问

如果请别人评审，建议重点问：

- 滚动和分页两套视图、共享内容模型的架构是否合理？
- TXT/EPUB 是否应该进一步改成“目录优先、正文按需”？
- Flutter 文本分页是否更适合逐页流式计算，而不是强行 isolate？
- 图文 EPUB 分页缓存应该缓存字符区间、block 布局，还是直接缓存渲染结果？
- 翻页动画期间暂停哪些后台任务比较合适？
- 漫画和图文 EPUB 的图片缓存预算有没有更好的策略？
