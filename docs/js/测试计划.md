## 1. 简介

### 1.1 测试目的

- 验证「自研设备报修」功能在 App 端和后台 Web 管理端的业务流程完整、数据正确
- 确保用户能正常提交报修，管理员能受理、派单、跟踪、关闭工单
- 发现并跟踪缺陷，评估功能是否达到上线标准

### 1.2 测试范围

#### ✅ 包含范围


| 端              | 测试内容                                                                                                 |
| --------------- | -------------------------------------------------------------------------------------------------------- |
| **App 端**      | 报修入口、设备选择、故障描述（文本/图片）、提交报修、查看报修记录、工单状态跟踪、消息/通知提醒           |
| **后台 Web 端** | 报修工单列表、筛选/搜索、查看详情、受理/拒绝、派单、填写处理结果、关闭工单、统计概览（如工单量、完成率） |
| **共同 & 联动** | App 提交后后台实时展示、后台状态变更后 App 同步更新、异常场景（网络、权限、数据一致性）                  |

#### ❌ 不包含范围

- 非自研设备的报修流程
- 支付、库存管理等外围系统（除非明确依赖）
- 大并发压测（仅做基础性能验证）

- 报修功能需求文档
- App 原型 / 交互稿
- 后台管理端设计稿
- 接口文档（如 App 与后台交互）

## 2. 测试策略

### 2.1 核心业务流程（端到端）

```text
【正常流程】
App用户登录 → 选择设备 → 填写故障描述 + 上传图片 → 提交报修
→ 后台管理员收到工单 → 受理 → 派单 → 维修完成 → 关闭工单
→ App端状态变为“已完成”
```

### 2.2 各端测试重点

#### App 端

- 兼容性：iOS / Android 主流版本 + 主流机型
- 网络：弱网、断网重提、WiFi/4G/5G切换
- 权限：相机、相册、通知权限拒绝后的表现
- 交互：返回、取消、快速点击、表单校验

#### 后台 Web 端

- 浏览器：Chrome / Edge（最新两个版本）
- 工单管理：列表分页、筛选、排序、导出（如有）
- 权限：不同角色（客服、维修员、管理员）可见/操作范围
- 操作日志：关键操作（受理、派单、关闭）有记录

#### 联动测试

- App 提交 → 后台实时刷新
- 后台状态更新 → App 状态同步（不要求实时，可拉取或推送）
- 同一工单在两端数据一致性（字段、状态、时间）

### 2.3 自动化策略（可选）

- 优先覆盖核心回归场景：提交报修 → 工单生成 → 状态流转
- App 端可做接口自动化，UI 自动化按资源决定
- 工具建议：Postman / JMeter（接口），Selenium / Appium（UI）

## 6. 缺陷管理

### 6.1 严重程度定义（针对报修功能示例）


| 等级 | 示例                                                 |
| ---- | ---------------------------------------------------- |
| 致命 | App 提交报修崩溃；后台无法打开工单列表；工单数据丢失 |
| 严重 | 提交成功后后台看不到；状态不同步；受理/派单功能无效  |
| 一般 | 图片上传失败但无提示；筛选条件不生效；文案错误       |
| 轻微 | UI 布局错位；提示语不友好；非必填校验不合理          |

### 6.2 缺陷状态流转

新建 → 已确认 → 修复中 → 待验证 → 关闭
（可扩展：重复、不予修复、延期处理）

## 7. 风险与应对


| 风险                        | 应对措施                               |
| --------------------------- | -------------------------------------- |
| App 与后台接口定义不一致    | 联调前置，接口评审 + Mock 先行         |
| 真机兼容性问题较多          | 提前借用真机或使用云测平台             |
| 后台状态变更后 App 同步延迟 | 明确同步机制（轮询/推送），设预期阈值  |
| 测试时间压缩                | 核心流程优先，非高优场景标注为低优先级 |
