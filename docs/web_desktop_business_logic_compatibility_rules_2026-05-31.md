# Web / Desktop 业务逻辑兼容规则

创建日期：2026-05-31  
适用范围：Web、Windows、macOS、Linux 的代码兼容、页面适配、业务链验收。  
排除范围：iOS、Android 的 UI、交互、平台能力、业务流程、验收任务。  
核心目标：**在不牵扯移动端的前提下，让 Web 和桌面端复用业务内核并完成可验证的业务闭环。**

## 0. 当前唯一执行口径

后续兼容工作以本文档为主规则。

- 不再把 iOS / Android 作为本轮兼容目标。
- 不为 Web / Desktop 需求改造移动端页面、交互、平台桥或原生目录。
- 不把移动端冒烟、截图、真机验证写入 Web / Desktop 阶段任务。
- iOS / Android 只作为“不可影响边界”存在：如果任务没有修改共享层或移动端相关代码，只记录“未涉及移动端”即可。
- 旧文档中的四端验证、移动端保护基线、Phase 记录保留为历史背景，不再作为新任务模板的主线。

一句话规则：

> Web / Desktop 要向业务内核靠拢，不能把 iOS / Android 拉进来陪跑。

## 1. 平台范围

### 1.1 本轮目标平台

目标平台只包括：

- Web
- Windows
- macOS
- Linux

任务命名统一使用 **Web / Desktop**。其中 Desktop 默认包含 Windows、macOS、Linux；如果某个能力只验证了 macOS，必须明确写成“macOS 已验证，Windows / Linux 待补验”。

后续 UI 设计和里程碑文档中可以统一使用“桌面端”口径；除非特别说明，桌面端包含 Web、Windows、macOS、Linux。

### 1.2 非目标平台

iOS / Android 不进入本轮任务拆分。

禁止把下面内容写成 Web / Desktop 任务的完成条件：

- Android 真机冒烟。
- iOS 真机冒烟。
- 移动端截图对比。
- 移动端交互重做。
- 移动端原生桥接改造。
- 移动端 UI 目录重构。

只有当 Web / Desktop 任务必须修改共享层时，才需要额外记录“是否可能影响移动端”。此记录是风险边界，不是把移动端纳入兼容目标。

## 2. 架构原则

最高原则：

**业务内核复用，平台能力隔离，表现层分流。**

### 2.1 可以共享

Web / Desktop 应优先复用这些平台无关内容：

- 纯 Dart model。
- repository contract。
- use case / service 中的平台无关业务规则。
- Riverpod provider 中的平台无关状态。
- 网络协议、数据转换、搜索、详情、目录、在线正文等业务语义。
- 阅读进度、收藏、书签、设置等抽象业务状态。

### 2.2 必须隔离

以下内容不得直接散落到页面层：

- `dart:io`
- `dart:ffi`
- `path_provider`
- 原生 SQLite
- 文件系统路径
- 本地图书导入与解析
- 本地 PDF / EPUB / MOBI / TXT 解析
- WebView
- 分享、剪贴板、外部打开
- 窗口控制、桌面菜单、快捷键
- 浏览器存储、路由刷新、CORS

处理方式必须优先使用：

- capability：声明平台能不能做。
- adapter：隐藏平台实现差异。
- conditional import：隔离 native / web import 链。
- wrapper：在外层选择 Web / Desktop 表现。
- facade：让页面只调用业务语义，不知道平台细节。

### 2.3 页面层规则

页面层只能做三件事：

- 渲染状态。
- 分发用户意图。
- 根据 capability 展示启用、禁用、隐藏或替代入口。

页面层不得：

- 直接 new repository / service。
- 直接依赖数据库实现。
- 直接调用 MethodChannel / EventChannel。
- 直接 import native-only 文件。
- 到处写 `kIsWeb`、`Platform.isXxx` 分支。

## 3. 业务链推进方式

后续不再按“平台技术块”推进，统一按业务链推进。

每条业务链必须能被用户真实操作，至少覆盖：

- 入口。
- 主页面。
- 主要弹窗、菜单、右键或更多操作。
- 公共组件。
- 状态与 provider。
- service / repository / datasource。
- 平台能力。
- 不支持能力的降级。
- Web / Desktop 验证。

每条业务链执行时必须同时拆成两条检查线：

- **平台兼容线**：确认代码能在 Web / Desktop 编译、运行，并且平台能力有 adapter、capability 或降级策略。
- **UI 展示线**：确认 Web / Desktop 有独立展示方案，不把移动端页面直接拉宽。

两条线都完成，业务链才允许标记为开发完成。

### 3.1 平台兼容线

平台兼容线解决“能不能跑、能力是否可用、不可用时怎么退”的问题。

每条业务链必须检查：

- 是否存在 `dart:io`、`path_provider`、原生 SQLite、WebView、文件系统、平台通道等 import 风险。
- Web 是否可以编译、刷新、前进后退、恢复必要状态。
- Desktop 是否可以构建、启动、窗口缩放，并正确处理文件路径、外部打开、剪贴板等能力。
- 数据库存储、凭证存储、缓存、日志、导入导出是否通过 adapter 或条件导入隔离。
- 不支持能力是否通过 capability 统一表达，而不是在页面里散落平台判断。
- 高风险能力是否隐藏、禁用、只读、外部打开、复制、下载或延期。

平台兼容线的产物：

- 能力差异结论。
- import 链风险结论。
- adapter / conditional import 待办。
- Web / Desktop 构建和运行验证记录。
- 不支持能力降级清单。

### 3.2 UI 展示线

UI 展示线解决“用户看到的 Web / Desktop 是不是像桌面应用，而不是手机页面横向拉伸”的问题。

每条业务链必须检查：

- 是否需要独立 Web / Desktop Shell、侧栏、详情面板或工具栏。
- 页面是否有最大宽度、多栏、网格、预览区或分组布局。
- 列表、卡片、表单、设置项在宽屏下是否信息密度合理。
- bottom sheet 是否在 Web / Desktop 替换为 dialog、popover、side panel 或 command surface。
- 长按、滑动、下拉刷新等移动端交互是否替换为右键、更多按钮、快捷键、刷新按钮或显式操作。
- hover、focus ring、selected state、滚轮、键盘导航是否可用。
- 390、600、840、1280、1600 等宽度下是否没有遮挡、溢出和无限拉宽。

UI 展示线的产物：

- 页面布局方案。
- 弹层 / 菜单形态方案。
- 键鼠交互方案。
- 关键视口截图或 widget smoke 记录。
- 宽屏问题清单。

### 3.3 推荐业务链顺序

| 顺序 | 业务链 | Web / Desktop 目标 | 风险 |
| --- | --- | --- | --- |
| 1 | 基础浏览链 | 首页、公告、关于、发现、空态、禁用态可浏览 | 低 |
| 2 | 最小登录与会话链 | 登录、会话恢复、退出登录 | 中 |
| 3 | 搜索到详情链 | 搜索、结果、详情、失败说明 | 中 |
| 4 | 在线阅读链 | 从详情进入在线章节、目录、设置、键鼠翻页 | 高 |
| 5 | 书架只读链 | 浏览已有书架、继续阅读、进入详情 | 高 |
| 6 | 设置与受限能力链 | 展示设置，明确不可用能力 | 中-高 |
| 7 | 本地图书导入链 | Desktop 文件导入；Web 上传或禁用 | 高 |
| 8 | 主题资源链 | 主题、背景、字体、图集的 Web / Desktop 策略 | 高 |
| 9 | 会员 / 支付 / 反馈链 | 外部浏览器、Web 收银台、反馈提交、诊断导出 | 高 |

## 4. Web / Desktop UI 规则

### 4.1 不把手机页面直接拉宽

Web / Desktop 页面必须有明确的宽屏策略：

- 内容最大宽度。
- 列表 / 网格切换。
- 侧栏或详情面板。
- 弹窗尺寸。
- hover / focus / selected 状态。
- 键盘、滚轮、右键或显式操作按钮。

移动端原布局不作为 Web / Desktop 的默认完成形态。

### 4.2 断点口径

推荐断点：

- `< 600`：窄屏兼容，仅做基础可用，不定义为移动端适配任务。
- `600 - 839`：紧凑宽屏，可启用窄侧栏或单栏最大宽度。
- `840 - 1199`：小桌面，可启用侧栏、宽内容区、双列。
- `>= 1200`：桌面，可启用多栏、网格、详情预览。
- `>= 1600`：宽桌面，提高信息密度，但正文仍需最大宽度。

### 4.3 交互替代

| 移动端常见入口 | Web / Desktop 替代 |
| --- | --- |
| 长按 | 右键菜单 / 更多按钮 |
| 左滑删除 | 显式删除按钮 / 右键菜单 |
| 下拉刷新 | 刷新按钮 / 快捷键 |
| 手势翻页 | 方向键 / Space / PageUp / PageDown / 滚轮 |
| 底部弹层 | dialog / popover / side panel |
| 触摸反馈 | hover / focus ring / selected state |
| 系统分享 | 复制链接 / 下载文本 / 外部打开 |

## 5. 平台能力降级规则

能力不可用时按下面顺序处理：

1. 有替代方案：显示替代方案。
2. 没有替代方案但用户需要知道：显示禁用态和原因。
3. 用户不需要感知：隐藏入口。
4. 高风险能力：默认隐藏或延期，不让用户点到失败路径。

### 5.1 常见能力口径

| 能力 | Web | Desktop | 首版策略 |
| --- | --- | --- | --- |
| 本地图书导入 | 上传文件或禁用 | `file_selector` | 先只读，后导入 |
| 本地图书解析 | 按格式单独验证 | 按格式单独验证 | TXT 优先，PDF/EPUB/MOBI 后置 |
| 本地 PDF | 需要 Web renderer | 可走桌面 renderer | Web 先禁用或只支持在线 |
| 字体导入 | 上传到浏览器存储或禁用 | 文件选择 + 应用目录 | Web 首版禁用 |
| 主题 / 背景 / 图集 | 预设只读或受限上传 | 文件选择 + 受管存储 | 先预设只读 |
| WebView 登录 | 不使用内嵌 WebView | 优先外部浏览器 | 外部浏览器或服务器登录 |
| 分享 | 复制链接 / 下载文本 | 复制 / 外部打开 | 不依赖系统分享 |
| 支付 | Web 收银台 | 外部浏览器 / Web 收银台 | 不接移动端支付流程 |
| 亮度 / 音量键 / 触感 | 不支持 | 不支持 | 不出现入口 |
| 电量 | 隐藏或未知 | 隐藏或未知 | 非阻断 |

## 6. 验证规则

### 6.1 开发完成

满足以下条件可标记为“开发完成”：

- 当前业务链代码路径已梳理。
- Web 或当前可用 Desktop 环境完成定向验证。
- `flutter analyze` 通过。
- 相关 widget / service 测试通过，或失败原因已记录。
- 未验证平台写明补验原因。
- 不支持能力已有禁用、隐藏、替代或延期结论。

### 6.2 跨端验收完成

满足以下条件可标记为“Web / Desktop 验收完成”：

- Web 完成真实操作。
- macOS 完成真实操作。
- Windows 完成真实操作。
- Linux 如作为发布目标，则完成真实操作；否则记录为非发布目标。
- 浏览器刷新、前进、后退不白屏。
- 桌面窗口缩放不遮挡、不溢出。
- 鼠标、键盘、滚轮路径可用。
- 不支持入口不会点击后失败。

### 6.3 发布完成

满足以下条件才允许发布 Web / Desktop：

- `flutter analyze` 通过。
- 关键测试通过，或已有明确豁免记录。
- Web build 通过。
- 目标 Desktop build 通过。
- 当前发布业务链完成 Web / Desktop 验收。
- 品牌标题、manifest、图标、窗口标题一致。
- 已知未完成能力有用户可理解的降级说明。
