# 书籍核心链路性能治理计划

更新时间：2026-05-05  
用途：作为“书架 / 详情 / 阅读 / 发现 / 搜索”核心书籍链路的统一性能治理文档，明确问题来源、治理顺序、执行清单、验收标准与回归口径。

## 1. 背景

当前用户高频使用的书籍相关功能存在以下体感问题：

- 进入书籍详情页卡顿，偶发先空白后显示
- 进入阅读页启动慢，正文和目录出现滞后
- 书架、发现、搜索列表滑动掉帧
- 本地书与在线书都能复现，说明问题不只在单一数据源

这类问题属于核心体验问题，优先级高于一般功能扩展。

---

## 2. 范围

本计划覆盖以下模块：

- `bookshelf`
- `book detail`
- `reader`
- `discover`
- `search`
- `home` 中的“继续阅读 / 书籍入口”

不包含：

- 同步系统本身的网络耗时优化
- 非书籍主链路页面的视觉动画调优
- 平台层 WebView / 登录页性能

---

## 3. 现状结论

已确认的性能问题主要来自四类：

### 3.1 Build 期同步 IO

典型风险：

- `existsSync()`
- `File(...)` 即时检查
- build 中路径归一化和本地资源探测

影响：

- 列表滑动掉帧
- 详情和阅读页首帧阻塞

### 3.2 Item 级异步解析

典型风险：

- 每个列表项单独 `FutureBuilder`
- 每个书卡单独查 metadata override
- 每个书卡单独准备封面展示态

影响：

- 滚动时频繁异步抖动
- 列表首屏构建不稳定
- 页面反复重建

### 3.3 Reader 启动链路串行过长

典型风险：

- 阅读设置、视觉覆盖、字体恢复、背景恢复、进度恢复、TOC 恢复、正文缓存恢复、detail fallback 全部串行

影响：

- 阅读页首屏慢
- 先空白后显示
- 已有缓存时仍然感觉慢

### 3.4 页面根部订阅过粗

典型风险：

- 页面根部 `watch(activeAdvancedThemeProvider)`
- 页面根部 `watch(coverGalleriesProvider)`
- 页面根部监听多个会导致整页重建的 provider

影响：

- 一处状态变化导致整页重建
- 列表区随无关状态一同刷新

---

## 4. 已完成治理

- [x] 封面路径解析增加内存缓存，降低重复同步文件判断
- [x] 详情页首帧直接进入 loading，避免短暂空白
- [x] 阅读页 bootstrap 的一部分独立读取并发化
- [x] `search` 改为列表级展示态缓存，不再每个 item 单独 `FutureBuilder`
- [x] `discover` 改为列表级展示态缓存，书单先显示，展示态后台回填

---

## 5. 治理原则

遵循 `docs/development_architecture_guardrails.md`：

- 页面只负责渲染、交互分发、订阅状态
- 不在页面 build 期做重 IO、重查询、重解析
- 能批量计算的，不做 item 级重复计算
- 能缓存的，不重复查
- 能延后到首屏后做的，不阻塞首屏

性能治理的一条核心原则：

- **首屏先可见，附加信息再补齐**

---

## 6. 最优治理方案

本项目不采用“纯懒加载”作为主方案，而采用：

- **列表级缓存 + 结果复用 + 首屏分阶段呈现**

原因：

- 纯懒加载会把卡顿推迟到滚动阶段
- 列表级缓存更适合高频书卡复用场景
- 分阶段呈现更适合 reader / detail 的首屏体验

## 12. 风险

- [ ] 书卡展示态批量缓存失效策略不清晰时，可能出现展示延迟刷新
- [ ] reader bootstrap 拆分不严谨时，可能引入“首屏快但状态补齐错位”
- [ ] 主题 / 图集相关 watch 下沉时，可能导致部分 UI 未及时刷新

对应要求：

- [ ] 每阶段只做一类主要重构
- [ ] 每阶段都补最小回归
- [ ] 避免同时重写多条链路
