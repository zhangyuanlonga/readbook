# 导入导出统一体验执行方案

更新时间：2026-05-08  
用途：作为“项目内导入/导出/外部应用打开导入体验统一治理”的唯一执行文档，统一范围、交互方案、阶段任务、验收标准和后续回填口径。

## 0. 结论先行

当前项目里的导入导出能力已经覆盖多个模块，但交互体验不统一，主要问题集中在：

- 点击后缺少明确过渡，用户会误以为没有响应
- 有的入口只有按钮 loading，没有阶段反馈
- 有的入口会直接执行重 I/O，造成 UI 卡顿感明显
- “完成”的语义不一致，尤其是本地图书导入场景
- “使用其他应用打开”属于横向导入能力，但当前没有被当作统一体验的一部分整体治理

一句话目标：

- **统一任务反馈骨架**
- **保留模块差异化内容**
- **把“其他应用打开导入”纳入同一套体验方案**

## 3. 当前问题拆解

### 3.1 共性问题

- [ ] 点击任务入口后，部分页面没有立即出现统一反馈
- [ ] 批量导入时缺少总量、当前项、阶段的稳定表达
- [ ] 完成态缺少统一收尾动作和结果确认
- [ ] 不同页面对“处理中”和“完成”的文案语义不一致
- [ ] 页面内旧文案与当前真实执行策略不一致

### 3.2 图书模块问题

- [ ] 历史文案仍存在“入库后后台继续解析”的表达
- [ ] 需要统一到“准备 -> 入库 -> 索引 -> 完成”
- [ ] “完成”必须等于“用户点开就能读”

### 3.3 外部应用打开问题

- [ ] 从其他应用打开文件时，目标页面之间的反馈体验还不统一
- [ ] 缺少“正在读取外部文件/正在接管导入”的统一过渡
- [ ] 文件不支持、缓存失败、导入失败的反馈样式仍偏分散

## 4. 统一交互设计

本次不建议只做一个组件，而是收敛成 `3` 套交互形态。

### 4.1 Task Overlay：全局任务遮罩

适用：

- 图书
- 书源
- 日志导出
- 字体管理页
- 外部应用打开进入后的主导入流程

展示字段：

- `title`：任务标题
- `message`：当前阶段说明
- `progress`：总进度，允许为空
- `progressLabel`：如 `2/8`
- 可选当前对象名，如文件名、书名、字体名

动效要求：

- [ ] 点击后 `100ms` 内必须出现反馈
- [ ] 遮罩进入 `180-220ms` 淡入上浮
- [ ] 文案切换使用 `AnimatedSwitcher`
- [ ] 进度条变化使用轻量补间
- [ ] 成功后停留 `400-700ms` 再退出

### 4.2 Inline Compact：紧凑内联态

适用：

- 外观页字体导入
- 阅读设置里的字体导入
- 未来其它 BottomSheet / Dialog 内的小型导入

展示字段：

- 按钮 loading
- 单行状态文案
- 必要时一条细进度条

设计要求：

- [ ] 不遮盖整页
- [ ] 不打断当前配置上下文
- [ ] 与全局任务态使用同一套文案语义

### 4.3 Queue Panel：队列面板

适用：

- 高级主题批量导入/批量导出

展示字段：

- 当前队列
- 当前处理项
- 总进度
- 单项结果
- 汇总结果

设计要求：

- [ ] 保留结果面板，不做“完成即消失”
- [ ] 允许局部失败，不阻塞整体结果呈现
- [ ] 与其他模块共享状态字段命名和视觉语言

## 5. 模块级展示方案

### 5.1 图书模块

目标语义：

- `准备文件`
- `写入书架`
- `建立目录/索引`
- `完成导入`

完成定义：

- [ ] 只有在目录可用、点开即可阅读时，才能显示“完成”

UI 方案：

- 书架主入口使用 `Task Overlay`
- 独立导入页保留页面内进度卡，但文案与阶段统一
- 完成态提供明确动作：
  - [ ] `立即阅读`
  - [ ] `返回书架`

### 5.2 书源模块

目标语义：

- `读取文件/内容`
- `解析书源格式`
- `保存书源`
- `完成`

UI 方案：

- 本地导入：`Task Overlay`
- 网络导入：`Task Overlay`
- 外部应用打开导入：`Task Overlay`
- 导出：`Task Overlay`
- 粘贴导入：页内表单提交后进入统一任务态

差异化内容：

- [ ] 更强调“当前文件名”
- [ ] 更强调“成功/失败数量”

### 5.3 字体模块

目标语义：

- `选择字体`
- `校验文件`
- `注册字体`
- `完成`

UI 方案：

- 字体管理页：`Task Overlay`
- 外部应用打开字体导入：`Task Overlay`
- 外观页 / 阅读设置页：`Inline Compact`

差异化内容：

- [ ] 保持轻量，不强行做复杂多阶段文案

### 5.4 高级主题模块

目标语义：

- `读取文件`
- `解析/解包`
- `导入资源`
- `生成主题`
- `完成`

UI 方案：

- 保持 `Queue Panel`
- 不强行替换成全局遮罩

差异化内容：

- [ ] 保留队列明细
- [ ] 保留结果页
- [ ] 只统一状态模型和视觉语言

### 5.5 日志导出模块

目标语义：

- `整理日志`
- `生成文件`
- `发起分享`
- `完成`

UI 方案：

- 使用轻量 `Task Overlay`

差异化内容：

- [ ] 不需要复杂进度，只需要明确处理反馈和收尾

### 5.6 外部应用打开链路

这是横向能力，必须单独治理。

统一目标语义：

- `接收到外部文件`
- `正在读取并缓存`
- `跳转到目标模块`
- `按模块类型执行导入`
- `完成 / 失败`

UI 方案：

- [ ] 所有外部文件导入都先显示“正在读取外部文件”
- [ ] 成功缓存后，切换为目标模块自己的导入任务态
- [ ] 不支持的文件类型使用统一错误样式
- [ ] 路由跳转前后状态文案保持连续，不出现“黑箱感”

## 8. 验收标准

### 8.1 通用标准

- [ ] 所有重型导入导出入口点击后 `100ms` 内有可见反馈
- [ ] 所有长任务都有当前阶段表达
- [ ] 所有批量任务都有总量和当前项表达
- [ ] 所有完成态都有清晰收尾，不让用户猜“接下来该干嘛”
- [ ] 错误态、取消态、完成态在不同模块使用统一语义

### 8.2 图书专项标准

- [ ] 图书显示“完成”后必须点开即可读
- [ ] 不再出现“文案说完成、实际还在解析”的情况

### 8.3 外部应用打开专项标准

- [ ] 从其他应用打开文件后，用户能明确知道应用已接管该任务
- [ ] 接管、缓存、跳转、导入四段过程有连续感
- [ ] 不支持文件类型时，用户能明确知道原因和归属模块

---

## 9. 推荐实施顺序

建议按以下顺序推进：

1. 图书模块
2. 书源模块
3. 字体模块
4. 日志与搜索失败导出
5. 高级主题模块
6. 外部应用打开链路专项统一

原因：

- 图书模块对“完成语义”最敏感，优先级最高
- 书源模块入口最多，统一收益最大
- 字体和日志改造成本较低，适合快速收口
- 高级主题复杂度最高，适合放在视觉语言统一阶段处理
- 外部应用打开是横向体验专项，适合在各模块基线稳定后统一收尾
