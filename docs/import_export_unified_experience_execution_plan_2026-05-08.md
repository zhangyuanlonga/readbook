# 导入导出统一体验执行方案

更新时间：2026-05-08  
用途：作为“项目内导入/导出/外部应用打开导入体验统一治理”的唯一执行文档，统一范围、交互方案、阶段任务、验收标准和后续回填口径。

补充回归：2026-05-09 根据真机录屏复测，发现外部图书导入和高级主题单项导出仍存在页面级浮层与底部任务面板叠加的问题；已补充专项修正记录和后续约束。

## 0. 结论先行

当前项目里的导入导出能力已经覆盖多个模块，但交互体验不统一，主要问题集中在：

- 点击后缺少明确过渡，用户会误以为没有响应
- 有的入口只有按钮 loading，没有阶段反馈
- 有的入口会直接执行重 I/O，造成 UI 卡顿感明显
- “完成”的语义不一致，尤其是本地图书导入场景
- “使用其他应用打开”属于横向导入能力，但当前没有被当作统一体验的一部分整体治理

一句话目标：

- **统一任务反馈骨架**
- **保留模块差异化内容**
- **把“其他应用打开导入”纳入同一套体验方案**

## 3. 当前问题拆解

### 3.1 共性问题

- [x] 点击任务入口后，部分页面没有立即出现统一反馈
- [x] 批量导入时缺少总量、当前项、阶段的稳定表达
- [x] 完成态缺少统一收尾动作和结果确认
- [x] 不同页面对“处理中”和“完成”的文案语义不一致
- [x] 页面内旧文案与当前真实执行策略不一致

### 3.2 图书模块问题

- [x] 历史文案仍存在“入库后后台继续解析”的表达
- [x] 需要统一到“准备 -> 入库 -> 索引 -> 完成”
- [x] “完成”必须等于“用户点开就能读”

### 3.3 外部应用打开问题

- [x] 从其他应用打开文件时，目标页面之间的反馈体验还不统一
- [x] 缺少“正在读取外部文件/正在接管导入”的统一过渡
- [x] 文件不支持、缓存失败、导入失败的反馈样式仍偏分散

## 4. 统一交互设计

本次不建议只做一个组件，而是收敛成 `3` 套交互形态。

### 4.1 Task Overlay：全局任务遮罩

适用：

- 图书
- 书源
- 日志导出
- 字体管理页
- 外部应用打开进入后的主导入流程

展示字段：

- `title`：任务标题
- `message`：当前阶段说明
- `progress`：总进度，允许为空
- `progressLabel`：如 `2/8`
- 可选当前对象名，如文件名、书名、字体名

动效要求：

- [x] 点击后 `100ms` 内必须出现反馈
- [x] 遮罩进入 `180-220ms` 淡入上浮
- [x] 文案切换使用 `AnimatedSwitcher`
- [x] 进度条变化使用轻量补间
- [x] 成功后停留 `400-700ms` 再退出

### 4.2 Inline Compact：紧凑内联态

适用：

- 外观页字体导入
- 阅读设置里的字体导入
- 未来其它 BottomSheet / Dialog 内的小型导入

展示字段：

- 按钮 loading
- 单行状态文案
- 必要时一条细进度条

设计要求：

- [x] 不遮盖整页
- [x] 不打断当前配置上下文
- [x] 与全局任务态使用同一套文案语义

### 4.3 Queue Panel：队列面板

适用：

- 高级主题批量导入/批量导出

展示字段：

- 当前队列
- 当前处理项
- 总进度
- 单项结果
- 汇总结果

设计要求：

- [x] 保留结果面板，不做“完成即消失”
- [x] 允许局部失败，不阻塞整体结果呈现
- [x] 与其他模块共享状态字段命名和视觉语言

## 9. 推荐实施顺序

建议按以下顺序推进：

1. 图书模块
2. 书源模块
3. 字体模块
4. 日志与搜索失败导出
5. 高级主题模块
6. 外部应用打开链路专项统一

原因：

- 图书模块对“完成语义”最敏感，优先级最高
- 书源模块入口最多，统一收益最大
- 字体和日志改造成本较低，适合快速收口
- 高级主题复杂度最高，适合放在视觉语言统一阶段处理
- 外部应用打开是横向体验专项，适合在各模块基线稳定后统一收尾
