# API 缓存策略

创建时间：2026-06-10

## 策略级别

| 策略 | 含义 | 默认 TTL | 适用场景 |
| --- | --- | --- | --- |
| `REALTIME` | 每次都请求服务端，不读本地 API 缓存 | 0 | 用户资料、权限、认证、私人书源、搜索结果 |
| `SHORT_CACHE` | 短期缓存，可通过刷新动作强制绕过 | 5 分钟 | 书籍详情、章节正文、公告列表 |
| `LONG_CACHE` | 长期缓存，数据变化低且不含敏感信息 | 6 小时 | 静态配置、分类、公共元数据 |

## 强制实时接口

- `/v1/auth/login`
- `/v1/auth/register`
- `/v1/auth/refresh`
- `/v1/auth/logout`
- `/v1/users/me`
- `/v1/me/profile`
- `/v1/me/book-sources`
- 私人书源增删改查接口
- 在线搜索接口
- 权限、会员、设备席位、模块开关接口

## 可缓存接口

- 公告列表和公告详情：`SHORT_CACHE`
- 书籍详情：`SHORT_CACHE`
- 章节正文：`SHORT_CACHE`，缓存 key 必须包含当前用户作用域
- 公共分类、公共配置：`LONG_CACHE`

## 约束

- 默认策略是 `REALTIME`。
- 带认证的缓存 key 必须包含当前 `userId`，避免多账号串用。
- 登出、账号切换、401 会话失效后，用户相关缓存必须失效或换作用域。
- 日志不得记录完整 token。
