## 1. 结论

高级主题编辑器建议先分成三层：

1. 颜色
2. 组件
3. 资源

其中“颜色”只放用户能直接理解的基础视觉语义，不把弹窗、卡片、按钮、搜索框等组件自己的细项全铺出来。

推荐颜色主列表保留 7 项：

1. 强调色
2. 页面背景
3. 次级背景
4. 主要文字
5. 辅助文字
6. 边框
7. 分割线

“弹窗背景”不再放颜色主列表，放到“组件 / 弹窗”里；“强度层”不再单独成区，合并到对应组件或资源项里。

“组件样式”首版不建议继续保留当前一组工程化开关。默认编辑路径只保留一个“圆角比例”，用 UI 设计工具常见的 4 个档位表达。

## 2. 关键语义确认

### 2.1 弹窗背景

“弹窗背景”不是页面背景，也不是普通卡片背景。

它应该表示弹窗和浮层容器内部的背景色，当前运行时主要对应：

| 作用位置 | 当前接线 |
| --- | --- |
| Dialog | `DialogThemeData.backgroundColor` |
| BottomSheet | `BottomSheetThemeData.backgroundColor` / `modalBackgroundColor` |
| PopupMenu | `PopupMenuThemeData.color` |
| 资源选择器、操作浮层 | 跟随 Dialog / BottomSheet / PopupMenu 的主题背景 |

因此 UI 文案建议放到“组件 / 弹窗”分组下，而不是放在颜色主列表里。

建议说明文案：

> 普通弹窗、菜单和底部面板的背景颜色。

默认值说明：

> 未设置时跟随主题默认浮层背景。

### 2.2 分割线

APP 里有明确的分割线使用场景，应该从“边框”里拆出来。

当前扫描结果：

| 类型 | 数量 |
| --- | ---: |
| `Divider` / `VerticalDivider` | 47 |
| `BorderSide` / `Border.*` | 234 |
| `outlineVariant` / `outlineColorValue` / `cardBorderColorValue` 相关使用 | 176 |

当前问题：

- 代码里没有独立 `DividerThemeData`。
- 分割线大多混用 `ColorScheme.outlineVariant`。
- `outlineVariant` 当前又被高级主题映射到 `cardBorderColor`。
- 用户看到“边框”时，不一定会想到列表分隔线、顶部栏底线、分组分隔线也会变。

建议把“分割线”作为颜色语义单独展示，不和“边框”合并。

短期低风险方案：

- UI 上新增“分割线”字段。
- 先复用现有弱描边颜色，也就是当前 `cardBorderColorValue` / `outlineVariant` 这条链路。
- 文案明确它影响列表分隔线、顶部栏底线、分组分隔线。

长期更干净方案：

- 在 `AppAdvancedThemeColors` 新增 `dividerColorValue`。
- 在 `ResolvedAdvancedThemePalette` 新增 `dividerColor`。
- 在 `AppTheme` 中补 `dividerTheme: DividerThemeData(color: palette.dividerColor)`。
- 把顶部栏底线、列表分割线、局部分组线逐步改为读取 `DividerTheme` 或统一 token。

### 2.3 强度层归属

“强度层”不建议继续独立放在颜色之后。它本质上不是一类用户对象，而是不同组件或资源的参数。

建议归属：

| 当前强度项 | 建议归属 | 说明 |
| --- | --- | --- |
| 组件阴影强度 | 高级参数 / 主题特效 | 不进默认组件样式；避免和圆角比例混在一起 |
| 卡片阴影强度 | 高级参数 / 主题特效 | 如果后续拆细，再作为效果项处理 |
| 弹窗阴影强度 | 高级参数 / 主题特效 | 如果后续拆细，再作为效果项处理 |
| 弹窗背景模糊 | 组件 / 弹窗 | 规划项；需要先有运行时支持再展示 |
| 壁纸遮罩透明度 | 资源 / 应用背景 | 背景资源的遮罩参数 |
| 壁纸不透明度 | 资源 / 应用背景 | 背景资源的显示参数 |
| 壁纸模糊程度 | 资源 / 应用背景 | 背景资源的模糊参数 |
| 阅读器遮罩透明度 | 资源 / 阅读背景 | 阅读背景资源的遮罩参数 |
| 阅读器背景不透明度 | 资源 / 阅读背景 | 阅读背景资源的显示参数 |
| 阅读器背景模糊程度 | 资源 / 阅读背景 | 阅读背景资源的模糊参数 |

## 3. 颜色分类建议

### 3.1 默认展示

这些字段建议默认展示，是主题最核心、最容易理解的颜色。

| 显示名 | 第二行说明 | 当前字段 / 映射 | 建议 |
| --- | --- | --- | --- |
| 强调色 | 按钮、链接和选中状态的颜色 | `primaryColorValue` | 保留默认展示 |
| 页面背景 | 页面底色 | `backgroundColorValue` | 保留默认展示 |
| 次级背景 | 分组、提示和说明区域的底色 | `elevatedSurfaceColorValue` | 保留默认展示 |
| 主要文字 | 正文和标题的颜色 | `textPrimaryColorValue` | 保留默认展示 |
| 辅助文字 | 提示和说明的颜色 | `textSecondaryColorValue` | 保留默认展示 |
| 边框 | 输入框、卡片和控件描边颜色 | `outlineColorValue` | 保留默认展示 |
| 分割线 | 列表、菜单和分组分割线颜色 | 建议新增；短期可复用 `cardBorderColorValue` / `outlineVariant` | 建议新增展示 |

### 3.2 高级参数

这些字段不建议放在颜色主列表里，可以放到对应组件或高级参数中。

| 显示名 | 当前字段 | 建议归属 | 原因 |
| --- | --- | --- | --- |
| 弹窗背景 | `surfaceColorValue` | 组件 / 弹窗 | 属于弹窗和浮层组件，不放颜色主列表 |
| 卡片背景 | `cardColorValue` | 组件 / 卡片 | 属于卡片组件，不是全局色 |
| 卡片文字 | `cardTextColorValue` | 组件 / 卡片 / 高级 | 多数情况下可由主要文字推导 |
| 卡片边框 | `cardBorderColorValue` | 组件 / 卡片 / 高级 | 和分割线、弱描边容易混淆 |
| 图标底色 | `iconBackgroundColorValue` | 组件 / 图标入口 / 高级 | 局部影响范围偏小 |
| 强调背景 | `primaryContainerColorValue` | 组件 / 选中态 | 更像选中背景或按钮/标签背景 |
| 辅助强调 | `secondaryColorValue` | 组件 / 按钮或标签 / 高级 | 可由强调色派生 |
| 按钮文字 | `buttonTextColorValue` | 组件 / 按钮 / 高级 | 应优先自动保证可读性 |
| 搜索框背景 | `searchFieldBackgroundColorValue` | 组件 / 输入框 | 组件专属字段 |
| 提示强调 | `noticeAccentColorValue` | 组件 / 标签提示 | 状态类局部语义 |
| 提示底色 | `noticeSurfaceColorValue` | 组件 / 标签提示 | 状态类局部语义 |
| 阴影色 | `shadowColorValue` | 组件 / 对应组件高级参数 | 跟随阴影强度归属到组件，不单独成区 |
| 壁纸遮罩色 | `wallpaperOverlayColorValue` | 资源 / 背景高级参数 | 跟随背景资源归属，不单独成区 |

## 4. 组件分类建议

组件区不应该只是“组件样式”一个大折叠。当前 `componentStyle` 有卡片、按钮、输入框、弹窗、导航、切换等多个样式枚举，对普通用户来说过重。

首版建议：

- 默认只保留“圆角比例”一个组件外观控制。
- 圆角比例采用 4 个档位，不使用连续滑杆。
- 卡片样式、按钮样式、输入框样式、弹窗样式、导航样式、切换样式先不放默认 UI。
- 这些旧字段底层保留，避免破坏旧主题和导入导出；后续如果需要再放到高级参数。

### 4.1 全局组件

| 字段 | 第二行说明 | 当前字段 | 建议 |
| --- | --- | --- | --- |
| 圆角比例 | 控制卡片、按钮、输入框和弹窗的整体圆角 | `componentStyle.globalRadiusScale` | 默认展示，4 档选择 |

建议 4 个档位：

| 档位 | 建议比例 | 用户感知 |
| --- | ---: | --- |
| 利落 | `0.75` | 更接近直角，工具感更强 |
| 标准 | `1.00` | 跟随 Lumina 默认圆角 |
| 柔和 | `1.20` | 更温和，适合阅读类应用 |
| 圆润 | `1.40` | 圆角更明显，视觉更轻松 |

说明：

- 不建议首版做连续滑杆，用户很难判断 83% 和 91% 的差异。
- 不建议首版暴露“组件阴影强度”，阴影属于效果/高级项，容易和背景、弹窗层级混在一起。
- 圆角比例不应该单独影响某一个组件，而应该作为全局设计语言。

### 4.2 卡片组件

| 字段 | 当前字段 | 建议 |
| --- | --- | --- |
| 卡片背景 | `cardColorValue` | 默认或高级均可，取决于是否希望卡片独立于页面 |
| 卡片样式 | `componentStyle.cardStyle` | 不默认展示；保留底层兼容 |
| 卡片文字 | `cardTextColorValue` | 高级参数 |
| 卡片边框 | `cardBorderColorValue` | 高级参数，注意不要和分割线混用 |
| 图标底色 | `iconBackgroundColorValue` | 高级参数 |

### 4.3 按钮组件

| 字段 | 当前字段 | 建议 |
| --- | --- | --- |
| 按钮样式 | `componentStyle.buttonStyle` | 不默认展示；按钮圆角跟随全局圆角比例 |
| 强调背景 | `primaryContainerColorValue` | 高级参数或选中态组件 |
| 按钮文字 | `buttonTextColorValue` | 高级参数，默认自动推导 |
| 辅助强调 | `secondaryColorValue` | 高级参数 |

### 4.4 输入框 / 搜索框组件

| 字段 | 当前字段 | 建议 |
| --- | --- | --- |
| 输入框样式 | `componentStyle.inputStyle` | 不默认展示；输入框圆角跟随全局圆角比例 |
| 搜索框背景 | `searchFieldBackgroundColorValue` | 默认展示或高级参数 |
| 输入框边框 | 读取 `outlineColorValue` | 不单独新增，跟随“边框” |

### 4.5 弹窗组件

| 字段 | 第二行说明 | 当前字段 / 映射 | 建议 |
| --- | --- | --- | --- |
| 弹窗背景 | 普通弹窗、菜单和底部面板的背景颜色 | `surfaceColorValue` | 默认展示；未设置时跟随主题默认浮层背景 |
| 弹窗样式 | 控制弹窗和底部面板的圆角、边框和层次感 | `componentStyle.overlayStyle` | 不默认展示；弹窗圆角跟随全局圆角比例 |
| 弹窗阴影 | 弹窗和底部面板的阴影强度 | 当前跟随 `componentStyle.shadowStrength` | 高级参数或后续特效项 |
| 弹窗背景模糊 | 弹窗和底部面板的背景模糊程度 | 规划项，当前无独立持久化字段 | 有运行时支持后再展示 |
| 弹窗边框 | 弹窗和底部面板的边缘线条颜色 | 读取 `outlineVariant` / `cardBorderColorValue` | 高级参数或后续统一到分割线 / 弱描边 |

### 4.6 导航组件

| 字段 | 当前字段 | 建议 |
| --- | --- | --- |
| 导航样式 | `componentStyle.navigationStyle` | 不默认展示；导航圆角跟随全局圆角比例 |
| 底栏图集 | `bottomNavGalleryId` | 放资源区，不放组件颜色区 |
| 导航文字 / 图标颜色 | 读取主要文字 / 辅助文字 | 不单独新增 |

### 4.7 切换 / 标签 / 状态组件

| 字段 | 当前字段 | 建议 |
| --- | --- | --- |
| 切换样式 | `componentStyle.switchStyle` | 不默认展示；切换形态后续再评估 |
| 提示强调 | `noticeAccentColorValue` | 高级参数 |
| 提示底色 | `noticeSurfaceColorValue` | 高级参数 |

## 5. 推荐编辑器结构

建议页面按以下顺序重排：

```text
高级主题编辑器
├── 颜色
│   ├── 强调色
│   ├── 页面背景
│   ├── 次级背景
│   ├── 主要文字
│   ├── 辅助文字
│   ├── 边框
│   └── 分割线
├── 组件
│   ├── 圆角比例：利落、标准、柔和、圆润
│   ├── 卡片：卡片背景
│   ├── 输入框：搜索框背景
│   └── 弹窗：弹窗背景
├── 高级参数
│   ├── 卡片样式、按钮样式、输入框样式、弹窗样式、导航样式、切换样式
│   ├── 卡片文字、卡片边框、图标底色
│   ├── 按钮文字、辅助强调、强调背景
│   ├── 提示强调、提示底色
│   ├── 阴影色、壁纸遮罩色
│   └── 其他低频颜色
└── 资源
    └── 3 列网格：应用背景、阅读背景、书籍封面、启动图集、底栏图集、主题特效
```

### 5.1 资源层网格

资源层不建议继续使用当前的大卡片上下堆叠方式，容易导致展示效果松散、预览大小不一致、扫描成本高。

建议改成 3 列网格，两行固定排序。这里的 3 列是资源层主形态；窄屏不能强行压缩卡片，而是给资源网格保留全局中屏最小宽度，不足时横向滚动。

| 第一列 | 第二列 | 第三列 |
| --- | --- | --- |
| 应用背景 | 阅读背景 | 书籍封面 |
| 启动图集 | 底栏图集 | 主题特效 |

资源卡片建议结构：

| 区域 | 内容 |
| --- | --- |
| 预览区 | 图片 / 图集缩略图 / 特效预览 |
| 标题 | 应用背景、阅读背景、书籍封面等 |
| 状态 | 已设置、未设置、跟随默认、当前主题引用 |

资源卡片内的强度参数归属：

| 资源卡片 | 内部参数 |
| --- | --- |
| 应用背景 | 图片、适配、透明度、遮罩、模糊 |
| 阅读背景 | 图片、适配、透明度、遮罩、模糊 |
| 书籍封面 | 绑定封面图集、预览封面效果 |
| 启动图集 | 绑定启动图集、预览启动图 |
| 底栏图集 | 绑定底栏图集、预览底栏图标 |
| 主题特效 | 使用 `ambient_effects_container: ^0.2.0` 提供雨、雪、落叶、樱花、萤火等氛围特效 |

说明：

- 每个资源卡片只展示核心状态，不在主网格里铺开全部参数。
- 点击资源卡片后进入对应设置面板，再展示适配、透明度、遮罩、模糊等细项。
- 这样资源层主界面保持 2 行 3 列，视觉更稳，也便于主题特效直接展示轻量预览。
- 当前实现要求资源网格固定 3 列，并使用全局中屏宽度作为最小网格宽度和固定卡片高度，避免页面局部断点、过瘦 `childAspectRatio` 导致卡片被拉长或预览拥挤。

## 6. 建议决策点

### 6.1 是否把“弹窗背景”从颜色区移到组件区

建议：移动到组件区。

原因：

- 当前实际作用范围不只是 Dialog。
- BottomSheet、PopupMenu、资源选择浮层都属于这条语义。
- “弹窗背景”是具体组件背景，不是全局基础颜色。

### 6.2 是否新增“分割线”

建议：新增。

原因：

- APP 内分割线场景明确存在。
- 用户能直接理解“边框”和“分割线”的区别。
- 当前把分割线塞进“边框”会让配置影响范围不够清晰。

### 6.3 “分割线”短期映射到哪里

建议分两步：

1. 第一阶段：先在 UI 分类和文案里新增“分割线”，短期复用 `cardBorderColorValue` / `outlineVariant`。
2. 第二阶段：模型新增 `dividerColorValue`，再逐步接入 `DividerThemeData` 和页面分割线。

这样风险最低，不会一次性动持久化、导入导出、主题兼容和大量页面。

### 6.4 是否保留独立“强度层”

建议：不保留。

原因：

- 用户不是按“强度”理解功能，而是按“弹窗、卡片、背景”理解功能。
- 强度参数应跟随它影响的对象出现。
- 合并后页面结构更直观：调应用背景时顺手调遮罩和模糊，调弹窗时顺手调阴影和模糊。
