# UI/UX 全面审查标准与优化方向

创建时间：2026-06-10  
角色：产品经理 + UI 设计师  
用途：**可执行的审查清单 + 优化方向**，用于全页面审查

---

## 📋 审查清单（每个页面必查）

### 一、视觉一致性审查

#### 1.1 圆角规范 ✓/✗

- [ ] 卡片圆角是否为 20dp
- [ ] 按钮圆角是否为 14dp 或 stadium
- [ ] 输入框圆角是否为 14dp
- [ ] 弹窗圆角是否为 16dp
- [ ] 底部弹层顶部圆角是否为 20dp

**不合格示例：**
- 卡片用了 16dp、12dp 等其他值
- 同一页面多种圆角混用

---

#### 1.2 间距规范 ✓/✗

- [ ] 页面内边距是否为 16dp
- [ ] 卡片内边距是否为 12dp
- [ ] 卡片间距是否为 8-12dp
- [ ] 组件间距是否为 8/12/16dp（不要出现 10、15、20 等随意值）
- [ ] 是否有过大间距（>32dp）或过小间距（<4dp）

**不合格示例：**
- 内边距用了 10dp、15dp、18dp 等随意值
- 同一页面间距不统一

---

#### 1.3 颜色使用 ✓/✗

- [ ] 是否使用 Theme.of(context).colorScheme 而不是硬编码颜色
- [ ] 是否避免直接使用 Colors.red、Colors.blue
- [ ] 文字颜色是否使用 onSurface / onSurfaceVariant
- [ ] 背景颜色是否使用 surface / surfaceContainerLow
- [ ] 边框颜色是否使用 outlineVariant

**不合格示例：**
- `color: Color(0xFF123456)` 硬编码
- `color: Colors.blue` 直接用 Material 颜色

---

#### 1.4 字体规范 ✓/✗

- [ ] 标题是否使用 titleLarge / titleMedium
- [ ] 正文是否使用 bodyLarge / bodyMedium
- [ ] 标签/辅助文字是否使用 bodySmall / labelMedium
- [ ] 是否避免自定义 fontSize（如 15、17、19 等随意值）

**不合格示例：**
- `fontSize: 15` 自定义大小
- 没有使用 TextTheme

---

### 二、交互体验审查

#### 2.1 点击反馈 ✓/✗

- [ ] 所有可点击元素是否有视觉反馈

- [ ] 桌面端是否有 hover 状态
- [ ] 触摸目标是否≥44x44dp（移动端）

**不合格示例：**
- 用 GestureDetector 没有视觉反馈
- 按钮点击没有任何变化

---

#### 2.2 加载状态 ✓/✗

- [ ] 首屏加载是否有加载指示器
- [ ] 列表加载更多是否有底部指示器
- [ ] 下拉刷新是否有刷新指示器
- [ ] 按钮操作中是否禁用并显示 loading
- [ ] 加载失败是否有错误提示和重试按钮

**不合格示例：**
- 点击按钮无响应，不知道是否在加载

---

#### 2.3 空状态 ✓/✗

- [ ] 列表为空是否有空状态提示
- [ ] 空状态是否包含：图标 + 文字 + 行动建议
- [ ] 空状态文案是否友好（不要"无数据"）
- [ ] 空状态是否提供下一步操作（如"添加第一本书"）

**不合格示例：**

---

#### 2.4 错误状态 ✓/✗

- [ ] 网络错误是否有提示

---

#### 2.5 确认操作 ✓/✗

- [ ] 删除操作是否有确认对话框
- [ ] 危险操作是否用红色标识
- [ ] 确认对话框是否说明后果（"删除后无法恢复"）
- [ ] 按钮顺序是否正确（左取消，右确定）

**不合格示例：**
- 删除直接执行，没有确认

### 八、状态管理审查（Riverpod 2.0）

#### 8.1 Provider 使用 ✓/✗

- [ ] 是否使用 ConsumerWidget（而不是 StatefulWidget）
- [ ] 是否避免不必要的重建（使用 select）
- [ ] 是否正确使用 autoDispose（避免内存泄漏）
- [ ] 异步数据是否使用 AsyncValue（处理 loading/error/data）

**正确示例：**
```dart
// ✅ 正确
class MyWidget extends ConsumerWidget {
  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final data = ref.watch(myProvider);
    return data.when(
      data: (value) => Text(value),
      loading: () => CircularProgressIndicator(),
      error: (e, st) => Text('错误: $e'),
    );
  }
}

// ❌ 错误：用 StatefulWidget 管理全局状态
class MyWidget extends StatefulWidget {
  // 用 setState 管理应该用 Provider 的状态
}
```

---

#### 8.2 Provider 命名 ✓/✗

- [ ] Provider 是否以 Provider 结尾
- [ ] StateNotifier 是否以 Notifier 结尾
- [ ] 是否避免 provider 嵌套过深（建议 ≤3 层）

**命名示例：**
```dart
// ✅ 正确
final bookListProvider = ...
final userStateNotifier = ...

// ❌ 错误
final books = ...  // 不明确
```

### 九、错误处理最佳实践

#### 9.1 错误分类 ✓/✗

- [ ] 是否区分网络错误、服务器错误、认证错误
- [ ] 是否提供友好的错误提示
- [ ] 是否提供重试按钮

**错误分类表：**

| 错误类型 | 提示文案 | 行动建议 |
|---------|---------|---------|
| **网络错误** | "网络连接失败" | [重试] 按钮 |
| **服务器错误** | "服务暂时不可用" | [重试] 或 [稍后再试] |
| **认证过期** | "登录已过期，请重新登录" | [去登录] |
| **权限不足** | "需要存储权限才能保存" | [去设置] |
| **数据格式错误** | "数据格式不正确" | [重试] 或 [联系客服] |

**实现示例：**
```dart
String getErrorMessage(dynamic error) {
  if (error is DioException) {
    switch (error.type) {
      case DioExceptionType.connectionTimeout:
        return '网络连接超时，请检查网络';
      case DioExceptionType.badResponse:
        if (error.response?.statusCode == 401) {
          return '登录已过期，请重新登录';
        }
        return '服务暂时不可用，请稍后再试';
      default:
        return '网络连接失败';
    }
  }
  return '操作失败，请重试';
}
```
