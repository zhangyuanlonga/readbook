# Flutter AppRead 项目总览

## 1. 项目背景

本项目目标是构建一个 Flutter 阅读 APP，并兼容开源阅读生态常见的书源规则格式（以 Legado 规则体系为主）。

核心价值：

- 利用已有书源生态，减少冷启动阶段的内容接入成本。
- 将复杂书源差异收敛到统一适配层，业务层只关注阅读体验。
- 可渐进迭代：先实现 MVP 可用，再提高兼容率和稳定性。

## 2. 项目愿景与边界

### 2.1 愿景

- 成为一个“可导入书源、可稳定阅读、可持续扩展”的跨平台阅读客户端。
- 在保持兼容性的前提下，提供优于通用工具型产品的阅读体验。

### 2.2 当前阶段边界（MVP）

本阶段仅覆盖：

- 文本小说阅读链路（搜索、详情、目录、正文）。
- 本地导入书源 JSON，手动启用/禁用。
- 常见规则语法支持（HTML 解析、正则、JSONPath）。

本阶段暂不覆盖：

- 漫画/听书源。
- 复杂登录流程、验证码、强反爬站点。
- 云同步与多端数据实时同步。

## 3. 成功标准（验收导向）

### 3.1 功能验收

- 可导入并保存书源配置。
- 可使用已启用书源完成一次完整阅读链路：搜索 -> 详情 -> 目录 -> 正文。
- 阅读器具备基础可用设置（字号、行距、背景主题、阅读进度保存）。

### 3.2 质量验收

- 10 个样本书源中，至少 6 个可跑通基本链路。
- 常见错误可定位（网络失败、规则提取失败、解析为空）。
- 主要页面交互流畅，无明显卡顿。

### 3.3 工程验收

- 模块边界清晰（UI / Domain / Data / Rule Engine 分层）。
- 关键流程有测试用例与回归样本。
- 文档可指导新成员在 1 天内搭建开发环境并开始开发。

## 4. 里程碑计划（建议 4 周）

### M1：基础工程与书源导入（第 1 周）

- 完成项目目录重构（features + core + data + domain）。
- 完成书源 JSON 导入、校验、存储。
- 完成书源管理页（列表、开关、删除、查看详情）。

### M2：阅读链路闭环（第 2 周）

- 接通搜索接口与结果解析。
- 接通书籍详情与目录解析。
- 接通正文抓取、清洗、展示。

### M3：稳定性与调试能力（第 3 周）

- 网络层增加重试、超时、Header/UA 支持。
- 增加规则执行日志与可视化调试页。
- 增加章节缓存策略与失败重试策略。

### M4：体验优化与发布准备（第 4 周）

- 阅读器体验优化（翻页、主题、字体等）。
- 兼容性回归测试与性能优化。
- 完成 Beta 发布检查清单。

## 5. 风险与应对

- 规则兼容复杂度高：采用“能力白名单 + 分阶段支持”策略，先支持高频语法。
- 站点反爬影响稳定性：建立源健康度指标，支持快速禁用异常源。
- 技术债堆积：任何临时兼容逻辑必须标注 TODO 并进入迭代清单。
- 合规风险：仅提供规则兼容能力，抓取行为需遵守站点条款和法律法规。
