## 0. 原则

统一按下面这条原则收敛：

- 启动和高频入口默认只读本地快照 / 缓存
- 配置变更时写回快照
- 少数明确场景才主动刷新远端

明确场景包括：

- 用户手动下拉刷新
- 登录态变化
- 进入会员中心、公告列表、更新检查等明确业务页
- 用户主动切换主题、启动图集、功能模块相关配置

## 2. Phase A：启动链拆除

目标：先把最不合理、最影响冷启动一致性的链路从启动路径中拿掉。

- [x] 移除“启动时读取完整主题后再解析启动图”的行为
- [x] 建立“启动图快照”结构
  - [x] 记录 `resolvedImagePath`
  - [x] 记录 `galleryId`
  - [x] 记录 `themeId`
  - [x] 记录 `updatedAt`
- [x] `StartupArtworkStore` 启动时只读快照，不再 `loadActiveTheme()`
- [x] 启动图关闭时直接清空快照
- [x] 启动图缺失时回退默认图，不进入主题解析链

验收：

- [x] 冷启动路径不再依赖 `AdvancedThemeService.loadActiveTheme()`
- [x] 原生冷启动空白问题风险下降
- [x] 启动图显示逻辑只依赖轻量本地记录

## 3. Phase B：主题与启动图联动改造

目标：保留主题绑定启动图能力，但把计算时机前移到“变更时”。

- [x] 主题应用时更新启动图快照
- [x] 主题保存时更新启动图快照
- [x] 高级主题启用 / 停用时更新启动图快照
- [x] 启动图集切换当前激活项时更新快照
- [x] 启动图集删除 / 重命名 / 图片变更且影响当前快照时更新快照
- [x] 建立快照更新入口，避免页面层各自拼逻辑

验收：

- [x] 主题切换后，下次启动直接使用最新启动图快照
- [x] 启动图效果与主题联动仍然存在
- [x] 启动链不再现场判断主题与图集关系

## 4. Phase C：高频入口缓存统一

目标：把“我的、书源、外观、会员能力入口”统一成同一套缓存优先模型。

- [x] 整理会员权益快照结构
- [x] 整理功能模块快照结构
- [x] 统一快照有效期与刷新策略
- [x] 登录成功后统一刷新会员 / 模块快照
- [x] 下拉刷新时统一刷新会员 / 模块快照
- [x] 进入会员中心时刷新权益
- [x] 我的页只读快照，不在页面返回时强刷
- [x] 书源页只读快照，不在页面初始化时强刷
- [x] 高级主题入口未确认权限时走“先补校验，再决定进入”

验收：

- [x] 高频入口不再每次打开都请求服务端
- [x] 会员用户不会被误判成未开通
- [x] 相关页面刷新时机一致、可预测

## 5. Phase D：启动 deferred 任务降干扰

目标：把保留的公告 / 更新 / 心跳 / 统计做成“存在感低，但该做仍做”。

- [x] 公告请求评估是否改为“当天首次打开才请求”
- [x] 更新检查评估是否改为“每日一次”或“用户主动检查为主”
- [x] 心跳保持节流，确认无需进一步收紧
- [x] visit 保持节流，确认桌面窗口切换场景不再过频
- [x] deferred 任务执行顺序再评估，尽量避开首屏首次交互期

验收：

- [x] 首屏可交互后前几秒内后台任务干扰降低
- [x] 服务端统计类请求不再显得“过于勤快”

## 6. Phase E：主题外观快照评估

目标：如果启动后仍存在主题补齐闪动，再做第二层收敛。

- [x] 评估是否需要“主题外观快照”
  - [x] palette
  - [x] backdrop
  - [x] app font family
- [x] 若需要，建立轻量主题外观快照
- [x] App 启动先读快照，再异步校正完整主题

说明：

- 这一阶段不是当前必做项
- 只有在启动时仍然存在明显主题闪动时才进入

## 7. 阶段顺序

按下面顺序执行：

1. Phase A：启动图从启动链拆除
2. Phase B：主题与启动图改成“变更时写快照”
3. Phase C：会员 / 模块高频入口缓存统一
4. Phase D：公告 / 更新 / 心跳 / 统计降干扰
5. Phase E：按需评估主题外观快照

## 8. 执行备注

- 每完成一项就直接打勾
- 优先做“低风险但收益大”的拆除
- 避免一次性重写所有页面逻辑
- 页面层尽量只消费快照与刷新入口，不再自行拼业务判断链
