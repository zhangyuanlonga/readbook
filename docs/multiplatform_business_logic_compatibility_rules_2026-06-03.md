# Web / Desktop / Mobile 业务逻辑兼容规则

创建日期：2026-06-03
适用范围：Android、iOS、Web、macOS、Windows、Linux 的代码兼容、页面适配、业务链验收。
核心目标：**业务内核复用，平台能力隔离，移动端稳定体验纳入影响面与回归矩阵，不再只作为“不可触碰边界”。**

## 0. 当前唯一执行口径

后续兼容工作以本文档为主规则。

- Android / iOS 是稳定移动端基线，也是后续多端改动的验收对象。
- Web / Desktop 适配不得借机重写成熟移动端体验，但共享层、业务链、平台能力或资源能力一旦改动，必须同步判断 Android / iOS 影响面。
- 移动端不是每个 Web / Desktop 任务的重构目标，但不再允许只写“未涉及移动端”就跳过所有判断。
- 任务收尾必须明确记录 Android、iOS、Web、macOS、Windows、Linux 的状态：已验证、未验证原因、非目标发布平台或延期补验。
- 平台专属 UI、手势、权限、原生桥、文件路径、支付、分享、亮度、音量键、WebView、后台能力都必须通过 capability / adapter / bridge 收口。

一句话规则：

> 多端共享业务内核，但每个平台只承诺符合自身使用习惯、权限模型和能力边界的体验。

## 1. 平台范围

### 1.1 目标平台

目标平台统一包含：

- Android
- iOS
- Web JS
- macOS
- Windows
- Linux

Web WASM 暂不作为默认交付目标，必须按独立专项记录依赖风险、插件兼容和替换方案。

### 1.2 平台定位

| 平台 | 当前定位 | 验收重点 |
| --- | --- | --- |
| Android | 稳定移动端基线 | 既有手势、路由、存储、权限、导入、阅读器体验不回退 |
| iOS | 稳定移动端基线 | Safe Area、返回手势、权限、文件访问、阅读器体验不回退 |
| Web JS | Web 首版目标 | 可构建、刷新恢复、浏览器存储、上传/下载降级、不可用能力说明 |
| macOS | 桌面优先验证目标 | 窗口、侧栏、键鼠、文件选择、外部打开、缓存/诊断导出 |
| Windows | 桌面发布补验目标 | 与 macOS 分开记录构建、路径、窗口和文件能力 |
| Linux | 桌面发布补验目标 | 与 macOS 分开记录构建、路径、窗口和文件能力 |

任务命名建议：

- 涉及全部平台：使用 **多端** 或 **全平台**。
- 只涉及 Web 和原生桌面：使用 **Web / Desktop**，并说明 Android / iOS 的影响判断。
- 只涉及移动端：使用 **Mobile** 或 **Android / iOS**，并说明 Web / Desktop 是否受影响。
- Desktop 默认指 macOS、Windows、Linux；如果把 Web 作为宽屏桌面体验一起验收，应写成 **Web / Desktop 宽屏**。

## 2. 架构原则

最高原则：

**业务内核复用，平台能力隔离，表现层分流，移动端稳定性可证明。**

### 2.1 可以共享

各端应优先复用这些平台无关内容：

- 纯 Dart model。
- repository contract。
- use case / service 中的平台无关业务规则。
- Riverpod provider 中的平台无关状态。
- 网络协议、数据转换、搜索、详情、目录、在线正文等业务语义。
- 阅读进度、收藏、书签、设置、主题、缓存预算等抽象业务状态。

共享不等于同一套页面形态。移动端、Web、Desktop 可以有不同 presentation，但状态语义、错误分类、能力开关和数据落点必须一致。

### 2.2 必须隔离

以下内容不得直接散落到页面层：

- `dart:io`
- `dart:ffi`
- `path_provider`
- 原生 SQLite
- 文件系统路径
- 浏览器存储、路由刷新、CORS
- 本地图书导入与解析
- 本地 PDF / EPUB / MOBI / TXT 解析
- WebView
- 分享、剪贴板、外部打开
- 窗口控制、桌面菜单、快捷键
- Android / iOS 权限、相册、文件选择、分享面板、支付、亮度、音量键、触感、后台任务、应用生命周期

处理方式必须优先使用：

- capability：声明平台能不能做。
- adapter：隐藏平台实现差异。
- bridge：封装原生通道和插件行为。
- conditional import：隔离 native / web import 链。
- wrapper：在外层选择移动端、Web 或 Desktop 表现。
- facade：让页面只调用业务语义，不知道平台细节。

### 2.3 移动端稳定规则

Android / iOS 的稳定体验需要被保护，但不是从兼容矩阵中移除：

- 不因 Web / Desktop 适配重写移动端页面、手势、路由、存储 key、数据库迁移或用户资产路径。
- 如必须抽取共享层，只做等价抽取，先说明旧分支结果与新 capability 结果是否一致。
- 涉及插件、权限、原生目录、manifest、Info.plist、MethodChannel、EventChannel 的改动，必须写明 Android / iOS 验证方式。
- 涉及阅读器、导入、资源、支付、登录、分享、亮度、音量键、缓存清理的改动，即使主要目标是 Web / Desktop，也必须补移动端回归。
- 无法验证真机时，可以先记录模拟器 / 代码级 / widget smoke 结果，但发布前必须补目标平台真实验证。

### 2.4 页面层规则

页面层只能做三件事：

- 渲染状态。
- 分发用户意图。
- 根据 capability 展示启用、禁用、隐藏、只读或替代入口。

页面层不得：

- 直接 new repository / service。
- 直接依赖数据库实现。
- 直接调用 MethodChannel / EventChannel。
- 直接 import native-only 或 web-only 文件。
- 到处写 `kIsWeb`、`Platform.isXxx`、`defaultTargetPlatform` 分支。

## 3. 业务链推进方式

后续不再按“平台技术块”推进，统一按业务链推进。

每条业务链必须能被用户真实操作，至少覆盖：

- 入口。
- 主页面。
- 主要弹窗、菜单、右键、更多操作或移动端手势。
- 公共组件。
- 状态与 provider。
- service / repository / datasource。
- 平台能力。
- 不支持能力的降级。
- Android / iOS / Web / Desktop 验证。

每条业务链执行时必须同时拆成三条检查线：

- **平台兼容线**：确认代码能在目标平台编译、运行，并且平台能力有 adapter、capability 或降级策略。
- **UI 展示线**：确认移动端、Web、Desktop 都有符合各自平台的展示方案。
- **移动端影响线**：确认 Android / iOS 既有体验不回退，或明确记录本次确实修改了哪些移动端行为。

三条线都完成，业务链才允许标记为开发完成。

### 3.1 平台兼容线

平台兼容线解决“能不能跑、能力是否可用、不可用时怎么退”的问题。

每条业务链必须检查：

- 是否存在 `dart:io`、`path_provider`、原生 SQLite、WebView、文件系统、平台通道等 import 风险。
- Android / iOS 是否需要权限、manifest / Info.plist、文件选择、相册、分享、支付、后台或原生桥验证。
- Web 是否可以编译、刷新、前进后退、恢复必要状态。
- Desktop 是否可以构建、启动、窗口缩放，并正确处理文件路径、外部打开、剪贴板等能力。
- 数据库存储、凭证存储、缓存、日志、导入导出是否通过 adapter 或条件导入隔离。
- 不支持能力是否通过 capability 统一表达，而不是在页面里散落平台判断。
- 高风险能力是否隐藏、禁用、只读、外部打开、复制、下载或延期。

平台兼容线的产物：

- 能力差异结论。
- import 链风险结论。
- adapter / conditional import 待办。
- Android / iOS / Web / Desktop 构建和运行验证记录。
- 不支持能力降级清单。

### 3.2 UI 展示线

UI 展示线解决“用户看到的是不是符合当前平台使用习惯”的问题。

每条业务链必须检查：

- Android / iOS 是否继续使用成熟移动端导航、AppBar、bottom nav、sheet、手势和触摸反馈。
- 移动端是否处理 Safe Area、软键盘、横竖屏、窄屏、文字缩放和触控命中区域。
- Web / Desktop 是否需要独立 shell、侧栏、详情面板或工具栏。
- 页面是否有最大宽度、多栏、网格、预览区或分组布局。
- 列表、卡片、表单、设置项在宽屏下是否信息密度合理。
- bottom sheet 是否在 Web / Desktop 替换为 dialog、popover、side panel 或 command surface。
- 长按、滑动、下拉刷新等移动端交互是否在 Web / Desktop 替换为右键、更多按钮、快捷键、刷新按钮或显式操作。
- hover、focus ring、selected state、滚轮、键盘导航是否可用。
- 390、600、840、1280、1600 等宽度下是否没有遮挡、溢出和无限拉宽。

UI 展示线的产物：

- 移动端布局和交互保持或调整结论。
- Web / Desktop 页面布局方案。
- 弹层 / 菜单形态方案。
- 键鼠与触控交互方案。
- 关键视口截图、widget smoke 或手工验证记录。
- 宽屏与窄屏问题清单。

### 3.3 移动端影响线

移动端影响线解决“是否真的没有影响 Android / iOS”的问题。

每条业务链必须检查：

- 是否修改共享 model、provider、repository、service、storage、route helper、theme token 或 adaptive 组件。
- 是否修改移动端会直接使用的页面、组件、sheet、dialog、reader overlay、手势识别或导航入口。
- 是否修改 Android / iOS 原生目录、权限、插件版本、构建配置或平台通道。
- 是否改变本地图书、字体、背景、封面、缓存、诊断、会话等用户资产路径。
- 是否改变阅读器翻页、滚动、进度保存、亮度、音量键、自动阅读、书签或目录行为。

移动端影响线的产物：

- Android / iOS 影响范围。
- 需要回归的移动端业务链。
- 未验证原因与发布前补验要求。
- 如果只是等价抽取，记录等价依据。

### 3.4 推荐业务链顺序

| 顺序 | 业务链 | Android / iOS 目标 | Web 目标 | Desktop 目标 | 风险 |
| --- | --- | --- | --- | --- | --- |
| 1 | 基础浏览链 | 既有首页、公告、关于、发现不回退 | 可浏览、刷新不白屏 | 侧栏/宽屏可浏览 | 低 |
| 2 | 最小登录与会话链 | 登录、会话恢复、退出不回退 | 外部登录或 Web 入口清晰 | 外部浏览器或桌面登录入口清晰 | 中 |
| 3 | 搜索到详情链 | 搜索、详情、换源不回退 | 搜索、结果、详情、失败说明 | 宽屏详情和失败说明 | 中 |
| 4 | 在线阅读链 | 手势、进度、设置、目录不回退 | 在线章节、目录、设置、键盘/滚轮降级 | 键鼠翻页、宽屏阅读、设置面板 | 高 |
| 5 | 书架链 | 书架、继续阅读、本地书入口不回退 | 浏览已有书架或只读降级 | 书架宽屏、继续阅读、本地书策略 | 高 |
| 6 | 设置与受限能力链 | 移动端设置入口和开关不回退 | 展示设置，明确不可用能力 | 展示设置，明确不可用能力 | 中-高 |
| 7 | 本地图书导入链 | Android / iOS 文件选择、解析、托管路径不回退 | 上传或禁用 | 文件导入、托管路径、解析 | 高 |
| 8 | 主题资源链 | 主题、背景、字体、图集不回退 | 预设只读或受限上传 | 文件选择 + 受管存储 | 高 |
| 9 | 会员 / 支付 / 反馈链 | 既有移动端支付、分享、反馈不回退 | Web 收银台、反馈提交、诊断导出 | 外部浏览器、反馈提交、诊断导出 | 高 |

## 4. UI 与交互规则

### 4.1 移动端规则

Android / iOS 默认保持成熟移动端体验：

- 一级导航继续使用现有移动端导航形态，除非单独立项。
- 主要操作保留触控友好的按钮、sheet、手势和命中区域。
- 列表、卡片、设置项不得因宽屏治理引入过密布局。
- Safe Area、状态栏、底部手势区、软键盘遮挡必须检查。
- 返回手势、系统返回键、深链返回栈必须保持可预期。
- 阅读器翻页、滚动、目录、设置、书签、进度保存必须作为移动端高风险回归项。
- 移动端专属能力如亮度、音量键、触感、系统分享、相册/文件选择、支付，不得用 Web / Desktop 降级规则覆盖。

### 4.2 Web / Desktop 宽屏规则

Web / Desktop 页面必须有明确的宽屏策略：

- 内容最大宽度。
- 列表 / 网格切换。
- 侧栏或详情面板。
- 弹窗尺寸。
- hover / focus / selected 状态。
- 键盘、滚轮、右键或显式操作按钮。

移动端原布局不作为 Web / Desktop 的默认完成形态。

### 4.3 断点口径

推荐断点：

- `< 390`：紧凑移动端。
- `390 - 479`：常规移动端。
- `480 - 599`：大屏手机或横屏小屏。
- `600 - 839`：紧凑宽屏，可启用窄侧栏或单栏最大宽度。
- `840 - 1199`：小桌面，可启用侧栏、宽内容区、双列。
- `>= 1200`：桌面，可启用多栏、网格、详情预览。
- `>= 1600`：宽桌面，提高信息密度，但正文仍需最大宽度。

### 4.4 交互替代

| 移动端常见入口 | Web / Desktop 替代 | 移动端要求 |
| --- | --- | --- |
| 长按 | 右键菜单 / 更多按钮 | 保留长按或显式更多入口 |
| 左滑删除 | 显式删除按钮 / 右键菜单 | 保留误触保护和确认 |
| 下拉刷新 | 刷新按钮 / 快捷键 | 保留下拉刷新或等价刷新入口 |
| 手势翻页 | 方向键 / Space / PageUp / PageDown / 滚轮 | 保留触控翻页 / 滚动配置 |
| 底部弹层 | dialog / popover / side panel | 保留移动端 sheet 体验 |
| 触摸反馈 | hover / focus ring / selected state | 保留触摸反馈和命中区域 |
| 系统分享 | 复制链接 / 下载文本 / 外部打开 | Android / iOS 优先系统分享面板 |

## 5. 平台能力降级规则

能力不可用时按下面顺序处理：

1. 有替代方案：显示替代方案。
2. 没有替代方案但用户需要知道：显示禁用态和原因。
3. 用户不需要感知：隐藏入口。
4. 高风险能力：默认隐藏或延期，不让用户点到失败路径。

### 5.1 常见能力口径

| 能力 | Android | iOS | Web | Desktop | 首版策略 |
| --- | --- | --- | --- | --- | --- |
| 本地图书导入 | 文件选择 / 系统文档入口 | 文件选择 / 系统文档入口 | 上传文件或禁用 | `file_selector` | Android / iOS 保持既有路径，Web / Desktop 单独适配 |
| 本地图书解析 | 按格式验证内存和编码 | 按格式验证内存和编码 | 按格式单独验证 | 按格式单独验证 | TXT 优先，PDF/EPUB/MOBI 分平台记录 |
| 本地 PDF | 保持既有移动端支持 | 保持既有移动端支持 | 需要 Web renderer | 可走桌面 renderer | Web 先禁用或只支持在线 |
| 字体导入 | 文件选择 + 受管目录 | 文件选择 + 受管目录 | 上传到浏览器存储或禁用 | 文件选择 + 应用目录 | 移动端不因桌面适配改路径 |
| 主题 / 背景 / 图集 | 相册/文件选择 + 受管存储 | 相册/文件选择 + 受管存储 | 预设只读或受限上传 | 文件选择 + 受管存储 | 用户资产路径必须稳定 |
| WebView 登录 | 保持既有桥接能力 | 保持既有桥接能力 | 不使用内嵌 WebView | 优先外部浏览器 | 新入口走 capability |
| 分享 | 系统分享面板 | 系统分享面板 | 复制链接 / 下载文本 / Web Share API | 复制 / 外部打开 | 不把移动端分享替换为桌面降级 |
| 支付 | 既有移动端支付或 H5 | 既有移动端支付或 H5 | Web 收银台 | 外部浏览器 / Web 收银台 | 支付能力必须分平台开关 |
| 亮度 / 音量键 / 触感 | 按 capability 展示 | 按 capability 展示 | 不支持 | 不支持 | Web / Desktop 不出现入口 |
| 电量 | 可用则展示，不可用显示未知 | 可用则展示，不可用显示未知 | 隐藏或未知 | 隐藏或未知 | 非阻断 |
| 诊断导出 | 系统分享 / 保存到可访问位置 | 系统分享 / Files 入口 | 下载或复制 | 保存文件或打开目录 | 日志必须脱敏 |

### 5.2 移动端权限与生命周期规则

Android / iOS 相关改动必须额外检查：

- 权限文案、manifest、Info.plist 是否齐全且与能力入口一致。
- 拒绝权限、永久拒绝权限、权限恢复后的 UI 状态是否可解释。
- 后台 / 前台切换、锁屏、来电、系统返回、热重启后的阅读进度是否稳定。
- 文件选择、相册选择、分享、支付、WebView、亮度、音量键等桥接能力是否有失败文案。
- 受管目录、缓存目录、用户资产目录不得被清理任务误删。

## 6. 验证规则

### 6.1 开发完成

满足以下条件可标记为“开发完成”：

- 当前业务链代码路径已梳理。
- 平台影响范围已记录到 Android、iOS、Web、macOS、Windows、Linux。
- `flutter analyze` 通过。
- 相关 widget / service 测试通过，或失败原因已记录。
- 至少完成当前可用目标平台的真实操作或构建验证。
- 共享层、平台能力或移动端相关代码有改动时，Android / iOS 至少完成定向 smoke、模拟器验证或记录发布前真机补验要求。
- 只要本次任务执行了 macOS、Windows、Linux 任一桌面构建，且当前机器具备移动端构建环境，必须同步执行 Android / iOS 构建；无法执行时必须写清阻塞原因、对应命令和补验责任人 / 补验机器。
- 未验证平台写明补验原因。
- 不支持能力已有禁用、隐藏、替代或延期结论。

### 6.2 多端验收完成

满足以下条件可标记为“多端验收完成”：

- Android 完成真实操作或明确记录仅代码级不回退的原因。
- iOS 完成真实操作或明确记录仅代码级不回退的原因。
- Web JS 完成真实操作，浏览器刷新、前进、后退不白屏。
- macOS 完成真实操作。
- Windows 完成真实操作，或记录 CI / 对应机器补验要求。
- Linux 如作为发布目标，则完成真实操作；否则记录为非发布目标。
- 移动端触控路径、系统返回、Safe Area、软键盘、阅读器关键手势不回退。
- 桌面窗口缩放不遮挡、不溢出。
- 鼠标、键盘、滚轮路径可用。
- 不支持入口不会点击后失败。
- 如果验收记录中包含任一 Desktop build，Android / iOS build 也必须有结果或明确阻塞记录；不能用 macOS / Windows / Linux 构建结果代表移动端构建。

### 6.3 发布完成

满足以下条件才允许发布目标平台：

- `flutter analyze` 通过。
- 关键测试通过，或已有明确豁免记录。
- Android 目标包构建通过。
- iOS 目标包构建通过或完成 `--no-codesign` 构建记录。
- Web JS build 通过。
- 目标 Desktop build 通过。
- 当前发布业务链完成对应平台验收。
- 品牌标题、manifest、图标、窗口标题、权限文案一致。
- 已知未完成能力有用户可理解的降级说明。

推荐 PR 基线：

```bash
flutter analyze
dart tool/check_architecture_guardrails.dart
dart tool/check_storage_governance_guard.dart
dart tool/check_route_inventory.dart
flutter build web --no-pub
```

平台相关发布前按目标平台补充：

```bash
flutter build apk --no-pub
flutter build ios --no-pub --no-codesign
flutter build macos --no-pub
flutter build windows --no-pub
flutter build linux --no-pub
```

## 7. 文档关系

本文档是后续多端业务逻辑兼容工作的主规则。

相关长期规则：

- `platform_development_rules.md`：当前 Web / Desktop / Mobile 平台规则。
- `ui_adaptive_design_rules.md`：当前 UI 与自适应设计规则。
- `development_architecture_guardrails.md`：当前多端架构开发约束。

历史里程碑文档中的“Web / Desktop 优先”“移动端只作为保护边界”等表述保留为阶段背景，不再作为新任务模板的主线。后续新增执行记录应优先引用本文档。
